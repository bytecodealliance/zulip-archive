As some of you know, I've created an are-we-fast-yet site for continuous Wasmtime/Cranelift benchmarking: https://bytecodealliance.github.io/are-we-fast-yet/

It runs our Sightglass benchmarks as often as it can (roughly every 2-3 hours) under callgrind (for ~determinism across machines) and plots the results over time. It also checks for statistically significant regressions between the current run and the previous one, and if it finds any it files an issue with the regression range, which benchmarks regressed, and how to reproduce the benchmark results. Here is an example regression issue. The goal is not to revert any performance regression, without context or nuance; it is simply to be aware of any regressions and make the choice to accept a regression consciously. Often we can reduce or remove the regression without undoing the bug fix or new feature, but we just needed to know that there even was a regression to avoid in the first place.

See also https://github.com/bytecodealliance/wasmtime/issues/13576

Right now, it is filing these regression issues against its own repository, so that I could work the kinks out before it is in front of a larger audience. I think I have pretty much worked them out at this point; it's been running for about three weeks. The false positive rate is pretty low now (I think the biggest risk is us getting inundated with false positives and ignoring the regression issues) but it still happens occasionally due to the ~2004 era branch predictor that callgrind hard codes. To counteract that, we ignore regressions when the majority of the regression is due to branch misses and instructions retired didn't shift. This has been pretty effective at filtering out noise due to LLVM code layout whims. We also compile with a single codegen unit to avoid similar issues with LLVM's inlining whims.

Anyways, the goal is to have it file issues on the Wasmtime repository, not its own. I think we are at a place where the infrastructure is mature enough to do that now, but before I make that switch, I wanted to double check that folks are on board with it.
