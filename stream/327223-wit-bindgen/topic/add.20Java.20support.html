Jeremy Grelle (Nov 12 2026 at 15:41):

I'm always happy to see more people wanting to build out Java + wasm tooling, but I think you might currently hit a bit of a dead end here. Though TeaVM is still under active development, the maintainer fully deprecated and removed the compiler's experimental wasi backend awhile back. IIRC it targeted wasi p1 and was fairly incomplete. I think the referenced TeaVM fork was aiming to make the support more complete, but TeaVM's maintainer was not interested in incorporating the changes from the fork.

There are at least 5 different open source projects (TeaVM, Bytecoder, j2cl, JWebAssembly, and Graal Native Image are the ones I know of) that implement some form of Java-to-wasm compilation. All of them target a JavaScript embedder (with a fair bit of generated JS runtime code required for the .wasm to work) as opposed to a standalone wasi environment.

I think it would be great to figure out what guest WIT bindings should look like for Java, and perhaps doing so in a central place decoupled from any of the compilers would further motivate their maintainers to add wasi support, which I could see as a worthy goal. But it's a bit of a chicken-or-egg problem.
