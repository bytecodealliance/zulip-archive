fitzgen commented on PR #15048:

I don't know about any weird platform gotchas -- you would know about those better than me. FWIW, the macro-generated layout tests are passing everywhere we run them in CI. We could always manually define a struct { tag, union } to avoid supporting enums in this macro, but my understanding is that this is actually identical to what repr(C) on an enum does (correct me if I'm wrong!).

Right now it is generating a separate region per variant field, which is valid for the use cases I currently have that never change enum variants while Wasm code has access to the enum, but I think you are right that doing so could cause problems down the line. So conservatively using one region per enum (or one for the tag and one for the data) at least for now seems like a good idea.
