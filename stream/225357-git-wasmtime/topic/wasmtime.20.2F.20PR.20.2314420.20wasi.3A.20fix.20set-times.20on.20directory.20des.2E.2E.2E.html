xia-chao opened PR #14420 from xia-chao:fix-wasi-dir-set-times to bytecodealliance:main:

Setting times on a directory descriptor fails with bad-descriptor, on both fd_filestat_set_times and descriptor.set-times.

Preopened directories are held open with O_PATH, and set_times called std::fs::File::set_times on that raw descriptor. On Linux that is futimens, which returns EBADF for an O_PATH fd. The same directory opened O_RDONLY sets its times fine, so the problem is O_PATH, not the directory.

The descriptor is otherwise fine: fd_filestat_get and stat succeed on it and report a directory, and the doc comment for fd_filestat_set_times says it adjusts an open file or directory.

Fixed by adding set_times_on_fd, which uses utimensat with an empty path and AT_EMPTY_PATH on Linux and Android so the call acts on the descriptor itself. Other platforms are unchanged.

Reproduced with a preview 1 module and a wasm32-wasip2 component calling set-times on the preopen.
