I have this use case where I use wizer to initialize JS component. During the initialization JS engine requires real wasi implementation but application defined imports should trap when called and their real implementation should be provided later when the component is running.

So far I was able to achieve this by keeping the following calls order: trap first and then register wasi. That approach is not working anymore after https://github.com/bytecodealliance/wasmtime/pull/13908 and I'm getting:

instance export error has the wrong type

This fix remembers which resource has already been visited and skips placeholder for that alias. The type checker then resolv each alias to the original resource.
