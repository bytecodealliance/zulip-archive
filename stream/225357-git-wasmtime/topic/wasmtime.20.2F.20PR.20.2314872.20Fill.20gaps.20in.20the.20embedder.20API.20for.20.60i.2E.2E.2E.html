This fills a few gaps in how implements and external-id are exposed to embedders:

  • Export lookups with attributes. Component::get_export_extern and Instance::get_export_extern work like get_export but return a types::ComponentExtern, so the export's attributes are available without iterating component_type().exports(). The data was already stored but never read. The C API gets wasmtime_component_get_export_extern and wasmtime_component_instance_get_export_extern, plus C++ wrappers. These take a &str name rather than impl ExportLookup, because attributes belong to the name an item is exported under.
  • Root type imports. Imports of types at the root of a component, e.g. (import "t" (external-id "x") (type (eq $u))), now show up in component_type().imports(), matching root type exports and nested component types. They still don't need to be defined in a Linker.
  • Lifetimes. ComponentExtern values from types::Component and types::ComponentInstance now borrow only from the type, not from the &Engine. This lets the bindgen! named_imports code drop its workaround of cloning the engine and collecting matching imports up front. One side effect there: if a lookup fails, earlier matching imports have already been defined in the linker.
  • #[non_exhaustive]. ComponentExtern is now #[non_exhaustive], so fields like the version suffix can be added later. This breaks code that builds it with a struct literal or destructures it exhaustively. Nothing in the repo does, and it's otherwise only produced by Wasmtime.

Closes #14862
