CompiledBlob::perform_relocations writes each relocation through a raw pointer at its offset into the definition. The only check is a debug_assert that the offset is below the size. Release builds have no check, and the debug one ignores the 4 or 8 bytes the write covers. The offsets come from safe APIs (DataDescription::write_data_addr and write_function_addr, and the relocs of define_function_bytes), so safe code can make finalize_definitions write past a definition. In a release build, an Abs8 relocation at offset 4 of an 8-byte data object overwrote the first 4 bytes of the next object.

define_data and define_function_bytes now check each relocation's full span and return ModuleError::Backend for one that doesn't fit. The debug_assert becomes an assert, since the unsafe writes rely on it. Both new tests fail on main in a debug build and pass with this change in debug and release builds.

Would you rather have a panic here than an error? I chose an error because both functions already return ModuleResult.
