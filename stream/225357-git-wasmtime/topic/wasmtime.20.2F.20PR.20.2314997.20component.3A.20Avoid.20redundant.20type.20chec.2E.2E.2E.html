delete previously checked is::<Tombstone>() on every deleted entry, even though the Tombstones are only used for debugging purposes. This added an extra downcast which should be elided in release builds. Overall this produces an improvement of about 4.5% in the p3_http_proxy benchmark.

Note that the improvements here seem to be a bit sensitive to inlining, so I added some explicit inlining which helped improve the benchmark results. A comparison against main when both use codegen-units=1 still shows an improvement in the p3_http_proxy benchmark, so I think the top line 4.5% improvement is coming from a mix of "real wins" and better inlining.

alexcrichton commented on PR #14997:

FWIW this was originally just intended as a debugging utility and aid, and IIRC the debug: bool parmeter is only there to aid with testing the implementation should the flag ever turn to true. In that sense I don't think it's worth going too far out of our way to keep supporting this -- if it's a perf problem I'd say we could just delete the support outright entirely since it's all off-by-default anyway. Dealing with sealed traits, impls, default type parameters, etc, to me feels a bit heavyweight relative to what it's trying to do.

Or, alternatively, for the perf problems you were seeing, is that all because debug: bool wasn't inlined to get const-propagated away? If that's the case then #[inline] could help, but I'd again consider keeping a debug-only utility like this a nice-to-have and would prioritize jettisoning it if it's causing problems.
