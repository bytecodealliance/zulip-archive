Issue: https://github.com/bytecodealliance/wasmtime/issues/14945

On aarch64, an i128 argument that doesn't fit in the remaining integer registers goes on the stack, but the next-register counter wasn't advanced. A following i64 was then assigned to x7. AAPCS64 C.13 (and clang/gcc, including on Darwin) pass it on the stack. This sets the counter to 8 in that case, for system_v and apple_aarch64 arguments only.

Cranelift-to-Cranelift calls were self-consistent, so this only affects signatures shared with C/Rust code. Wasmtime doesn't pass i128 across calls.

Testing: new cases in isa/aarch64/call.clif (previously compiled to mov x0, x7, now a stack load). The aarch64 and runtests filetest directories pass.
