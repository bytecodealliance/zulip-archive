On aarch64 without LSE, atomic_cas.i32 is lowered to AtomicCASLoop, which compared the loaded value against the expected value with a full 64-bit cmp x27, x26. The ldaxr zero-extends the loaded value, but the upper 32 bits of the register holding the i32 expected value are unspecified in the aarch64 backend. For example, ireduce.i32 of an i64 reuses the same register. When those bits are nonzero, the compare fails even though the low 32 bits match, so the exchange is skipped and the old value is returned. CLIF semantics, the interpreter and the other backends all perform the exchange.

I8/I16 already compare with uxtb/uxth. This PR does the same for I32 and emits cmp x27, w26, uxtw.

Reduced repro:

function %cas32(i64, i32, i32) -> i32, i32 {
    ss0 = explicit_slot 8
block0(v0: i64, v1: i32, v2: i32):
    v3 = stack_addr.i64 ss0
    store.i32 v1, v3
    v4 = ireduce.i32 v0
    v5 = atomic_cas.i32 v3, v4, v2
    v6 = load.i32 v3
    return v5, v6
}
; run: %cas32(0x100000005, 5, 7) == [5, 7]   ; aarch64 (no LSE) returned [5, 5]
