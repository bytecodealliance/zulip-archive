alexcrichton opened PR #14827 from alexcrichton:pr to bytecodealliance:main:

This commit fixes an issue where a StreamAny can be used to re-type a future or stream in a manner that can cause a panic within Wasmtime in certain host situations. The fix here is to unconditionally perform a type-check when lowering a future or stream into a guest. This is already required for {Stream,Future}Any, and it's additionally required in this issue when the T in StreamReader<T> contains a StreamAny, for example. This technically makes the static type-check of StreamReader<u32> redundant, but it seems best to fully close this hole since #14733 was not a complete fix for this class of issues.
