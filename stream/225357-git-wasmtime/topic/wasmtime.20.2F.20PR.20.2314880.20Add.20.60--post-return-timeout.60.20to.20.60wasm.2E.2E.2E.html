-W timeout also bounded how long a WASIp3 component instance may keep running after all of its requests have produced responses, for example while it is still streaming a response body, so a short request timeout cut off long-lived streams. Add --post-return-timeout to bound that phase on its own. It defaults to -W timeout, so behavior is unchanged unless it is set.

Like -W timeout, setting the option runs blocking WASI filesystem calls on background threads and enables epoch interruption, so the deadline is enforced while the guest is blocked in a filesystem call or never yields. RunCommon::configure_wasip2 now takes the blocking decision as a parameter, since run and serve derive it differently.
