Problem

ObjectModule::define_data calls add_section for every data object that has a custom section. A Mach-O object holds at most 255 sections, so ObjectProduct::emit fails with Too many sections: 0x12d once a module defines more data objects than that.

This happens in practice with rustc_codegen_cranelift on aarch64 macOS: every inventory::submit! static goes into __DATA,__mod_init_func, and building nautilus-model hits the limit.

Change

On Mach-O, reuse an existing section when segment, name, SectionKind, and Mach-O flags all match, as LLVM does when it merges sections with the same name. ELF and COFF output is unchanged.

Testing

  • New macho_data_objects_share_custom_section in cranelift/object/tests/basic.rs: defines 300 objects in __DATA,__mod_init_func,mod_init_funcs plus one in a second custom section, then checks there is exactly one section of each with the expected size and section type. It fails without the fix (Too many sections: 0x12d) and passes with it.
  • cargo test -p cranelift-object, cargo fmt --check, and cargo clippy -p cranelift-object --all-targets pass.
