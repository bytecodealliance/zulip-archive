netliomax25-code opened PR #14884 from netliomax25-code:wasi-nn-witx-guest-error-trap to bytecodealliance:main:

The WITX wasi-nn host panics when a guest passes a bad pointer or a non-UTF-8 string, because nn_errno_from_wasi_nn_error hits unimplemented!() for WasiNnError::GuestError. For example, load_by_name with a name pointer past the end of linear memory takes down the host with "not implemented: guest error conversion" instead of failing the call.

This returns the GuestError as a trap. Invalid enum arguments already trap in the wiggle glue, and WASIp1 traps on out-of-bounds pointers, so this follows the same model. The new unit test calls load_by_name with an out-of-bounds pointer and with invalid UTF-8; it panics before this change and passes after.

Tested with cargo test -p wasmtime-wasi-nn --lib, with and without default features.
