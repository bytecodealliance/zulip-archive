cfallin opened PR #15183 from cfallin:memory-range-api to bytecodealliance:main:

In order to support record/replay, we need precise information about when memory is mutated (so we can capture memory side-effects properly). Wasmtime's current APIs provide slices (immutable or mutable) over an entire memory, and the canonical idiom is then to subslice them further; something like memory.data_mut(&mut store)[start..end]. We can support R/R with this but it ain't gonna be efficient: we'd have to capture the whole memory because we don't know about the subsequent sub-slice.

This PR adds Memory::data_range and Memory::data_range_mut to borrow only one range of a memory (and an API alongside Memory::data_and_store_mut as well, with a bit more fiddly detail involving a MemoryRanges struct that represents the memory capability without requiring a full reborrow/rederivation of the borrowed T as well).

This PR also updates both the component-model canonical ABI implementation, and Wiggle, to use this more precise API, so when we eventually implement R/R, we will have precise/small/efficient traces for all of WASIp{1,2,3} programs.
