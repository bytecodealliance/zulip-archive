This is step 2 of implementing MMU-triggered interruption of Wasm, broken off the large #12990 for ease of review. Additional background is in the original feature suggestion: #1749.

This PR consists of...

  • A Config option, for controlling runtime behavior
  • An engine tunable, for controlling whether interruption checkpoints get compiled into JITted wasm
  • A has_mmu_interruption cfg flag in crates/wasmtime for avoiding compilation of MMU-interruption runtime code on unsupported platforms or compile-time configurations
  • A second has_mmu_interruption, in the top level, for gating compile-time code in the CLI.

These controls will keep to-be-landed parts of MMU interruption from running until the entire feature is in place. Keep in mind not all of these are read by anything yet.

No vestige of MMU interruption is yet visible from the commandline.

erikrose edited PR #14929:

This is step 2 of implementing MMU-triggered interruption of Wasm, broken off the large #12990 for ease of review. Additional background is in the original feature suggestion: #1749.

This PR adds 3 flags:

  • The has_mmu_interruption_runtime cfg predicate, which indicates whether runtime support is available for MMU interruption on the current host
  • A HAS_MMU_INTERRUPTION_RUNTIME const, with the same semantics. Other crates cannot see our cfg predicate, so we provide this for them to consult at runtime.
  • An mmu_interruption engine tunable, which adds MMU interruption support to compiled Wasm.

These controls will keep to-be-landed parts of MMU interruption from running until the entire feature is in place. Keep in mind not all of these may be read by anything yet.

No vestige of MMU interruption is yet visible from the commandline.

One thing I'll note is that #[cfg] in tests is going to be quite brittle over time. These cause a lot of churn when new support is added, they're replicated in many locations so it's diffcult to update, and these frequently change when new support is added/evolved over time. Where possible I would recommend using normal functions or something outside of #[cfg]. That will prvent warnings about dead code/imports/etc and it'll additionally make it much easier to update things overtime. For example this test can be reduced to:

fn is_supported() -> bool { /* ... */ }

#[test]
fn support_matches_expected() {
    // ...
    assert_eq!(Engine::new(&config).is_ok(), is_supported());
}
