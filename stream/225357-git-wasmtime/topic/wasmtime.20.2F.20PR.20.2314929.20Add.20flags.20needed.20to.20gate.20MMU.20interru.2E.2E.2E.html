erikrose opened PR #14929 from erikrose:mmu-interrupt-config to bytecodealliance:main:

This is step 2 of implementing MMU-triggered interruption of Wasm, broken off the large #12990 for ease of review. Additional background is in the original feature suggestion: #1749.

This PR consists of...

  • A Config option, for controlling runtime behavior
  • An engine tunable, for controlling whether interruption checkpoints get compiled into JITted wasm
  • A has_mmu_interruption cfg flag in crates/wasmtime for avoiding compilation of MMU-interruption runtime code on unsupported platforms or compile-time configurations
  • A second has_mmu_interruption, in the top level, for gating compile-time code in the CLI.

These controls will keep to-be-landed parts of MMU interruption from running until the entire feature is in place. Keep in mind not all of these are read by anything yet.

No vestige of MMU interruption is yet visible from the commandline.
