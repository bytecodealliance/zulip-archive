alexcrichton opened PR #15122 from alexcrichton:remove-spec-interpreter to bytecodealliance:main:

This commit removes part of the differential fuzzer which fuzzes against the spec interpreter itself. This was discussed a bit in #13561 but the general reasons are:

  • This has historically been a bit of a drag on infrastructure. Figuring out how to align and install OCaml is a relatively big lift compared to our other infrastructure requirements (most developers don't have it locally).

  • This is now causing issues on CI through #15117 where installation of OCaml is changing version-to-version in Ubuntu.

  • The spec interpreter hasn't been updated in quite a long time and is at a very old version at this point. This means that many proposals to wasm are not actually fuzzed.

  • Fuzzing hasn't turned up any issue in a very long time. Additionally once we're differentially executing against at least one other implementation (e.g. v8 or wasmi) the value of adding more implementations goes down.

Overall I'm reaching the conclusion that the best thing to do at this time is to just remove it. We could always consider re-adding it in the future, but it may want to be through some sort of alternative harness, maybe out-of-repo, or maybe even just a temporary one-off fuzzer.

Closes #13561
