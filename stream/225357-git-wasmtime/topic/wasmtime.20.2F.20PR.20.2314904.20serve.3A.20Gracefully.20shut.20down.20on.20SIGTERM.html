This makes wasmtime serve shut down gracefully on SIGTERM, the same as on ctrl-c. Discussed in the issue: https://github.com/bytecodealliance/wasmtime/issues/14899

Before, SIGTERM (sent by systemd and docker) killed the server immediately with exit status 143. Now it takes the graceful shutdown path and exits 0. A second signal still short-circuits waiting for remaining connections.

Validation: I ran wasmtime serve on a small hand-written WAT component and sent SIGTERM. Before the change it exited 143; after, it exits 0. I did not add an automated test, because the wasm32 targets needed to build the test programs aren't installed on my machine. I also did not test with in-flight requests, on non-Unix platforms, or run clippy.
