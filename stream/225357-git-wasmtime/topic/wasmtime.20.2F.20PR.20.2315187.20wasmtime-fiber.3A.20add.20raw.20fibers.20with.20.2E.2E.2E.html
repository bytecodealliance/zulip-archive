In order to support record/replay with reversible debugging, we need the ability to snapshot and resume to earlier execution states.

The general strategy I've taken in my prototype branch is to snapshot the whole execution state of a Wasm store by literally memcpy'ing its activation stacks, and memcpy'ing those snapshots back.

In order to do this without creating UB in Rust, however, we need to run the Wasm on a stack with no Rust frames. Later commits will introduce new kinds of trampolines that actually do this, by using Cranelift-compiled code both at the "entry end" (the initial trampoline that calls whatever Wasm entry point) and the "exit end" (trampolines for hostcalls, by yielding back out with a special code indicating we're doing a call). However, a prerequisite for this is a new kind of fiber that does not take a Rust closure as its entry point.

This PR introduces exactly that: a "raw fiber" is one that takes a raw function address as an entry point (an unsafe "C" fn), with a fixed defined signature, and invokes that. The entry-point function must never return; instead, it should terminate its execution by yielding one last time with a user-defined protocol that then causes the yieldee to drop the raw fiber, thus freeing the stack.

This PR then provides a snapshot/resume API. The idea is that the snapshot captures the state of the stack and the saved stack pointer. It is the responsibility of the user to ensure that the semantics of resuming multiple times to a raw fiber snapshot are sensible (e.g. by controlling the code entirely, i.e. as Cranelift-compiled JIT code, and by snapshotting/restoring all other state that that code uses).

This PR supports Windows as well; this is a little trickier than the Unix case because we use Windows' kernel-level fibers in this fiber library. We need to interpose a special frame with a known shape in the Windows case so that we can save and restore the stack pointer for arbitrary snapshots.
