kestred opened PR #15330 from kestred:cranelift-gvn-depth to bytecodealliance:main:

Fixes #15263.

depth_of_block_in_gvn_map finds a block by scanning gvn_map_blocks, which is quadratic when the dominator tree is
deep. This records each block's index when it is pushed and looks it up, with a debug assertion that the two agree.

For my ordinary test corpus (~20 programs of various shapes) compile time is unchanged.

For a pathological program (a chain of 16,384 blocks) at opt_level=speed, the egraph pass goes from 1.28 s to 0.23 s.
