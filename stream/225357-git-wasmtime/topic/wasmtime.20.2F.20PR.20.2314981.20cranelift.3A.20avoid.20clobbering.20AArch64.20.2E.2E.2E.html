Fixes #14946.

Problem

When loading a nested stack_limit global value on AArch64, x16 may hold the base of the next load. Materializing a large offset into x16 destroys that base and yields a bad address or a crash.

Change

Use the reserved x17 temporary for offset materialization when the base register is x16; otherwise retain x16.

Regression coverage

Add a Cranelift .clif run test for nested stack-limit loads with large negative offsets, covering AArch64 and x86_64.

Validation

Not compiled or run locally. Please validate with Cranelift filetests and AArch64 CI before marking ready.
