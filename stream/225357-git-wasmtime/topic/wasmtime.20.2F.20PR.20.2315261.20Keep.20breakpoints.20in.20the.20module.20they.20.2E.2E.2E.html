In a component, all the core modules share one frame table. When setting or removing a breakpoint, Wasmtime looked up breakpoint sites by PC alone, and PCs are relative to each module. So if two modules had code at the same PC:

  • setting a breakpoint in one module also stopped the other
  • removing a breakpoint from one module also removed the other's
  • a breakpoint with no later opcode in its own module could slip into another module's code

#15182 and #15194 fixed this for single-stepping by skipping other modules' sites.

This PR fixes it in the frame table itself:

  • Breakpoint sites are now sorted by module, then PC, instead of by PC only.
  • Every lookup (set, remove, slip, single-step) first narrows to the requested module's range of sites.

The existing two-module component test was padded so the modules' PCs never overlapped, which hid the bug. It now has both modules use the same PCs, and there are new tests for setting, removing and slipping breakpoints in one module without affecting the other.
