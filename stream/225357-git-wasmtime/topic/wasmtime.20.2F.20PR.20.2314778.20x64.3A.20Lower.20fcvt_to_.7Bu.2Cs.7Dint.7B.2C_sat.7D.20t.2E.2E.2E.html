Compiling fcvt_to_{u,s}int{,_sat} with an i8 or i16 result panics on x64 in emit.rs. The lowering rules accept those types, but the conversion sequences only emit 32-bit and 64-bit forms. aarch64, riscv64 and s390x already lower them. Wasm never produces these results, so only CLIF reaches the panic.

This converts to i32, then clamps the result or traps with int_ovf when it's out of range. The unsigned forms can use the signed conversion, since anything at 2^31 or above already saturates or traps there.

x86_64 now runs the existing i8 and i16 runtests. Runtests can't expect a trap, so I also ran 122 NaN and out-of-range inputs natively, and every one trapped. The run line I fixed in fcvt-sat-small.clif named the signed function under the unsigned one. test run ignores the name and calls the function above it, so it never failed.

Fixes #4897.
