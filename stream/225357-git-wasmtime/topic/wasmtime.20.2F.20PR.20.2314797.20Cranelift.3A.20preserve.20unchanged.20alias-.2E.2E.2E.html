Hello, I have attempted to fix #14312.
In the previous implementation, new extents were generated at branch merge points. This meant that even if a specific memory region had not been written to, the read operation following a merge could not reuse previous results, leading to redundant reads.
I have introduced a table to track extents for each memory region and added checks for writes occurring along the various paths leading up to a merge point. For regions that have not been modified—provided they pass the necessary state checks—the original markers are preserved, allowing existing optimization logic to eliminate redundant reads. A test case has also been added.
Testing locally with signals-based traps disabled—using the original .wasm program provided in the issue—execution time decreased by approximately 23%, while compilation time increased by about 0.9%.

Wasmtime GitHub notifications bot (Oct 22 2026 at 18:07):

:speech_balloon: fitzgen created PR review comment:

Hard-coding None as the region argument to extent_for is done a few times, but requires that the LastStore is also not Unknown, or else this could lead to miscompiles. The existing call sites are sound, but this feels pretty subtle and like something we could easily accidentally mess up in the future.

I think we could avoid this footgun by changing extent_for into something like this:

    fn extent_for(&self, func: &Function, inst: Inst) -> u32 {
        match self.stores.get_last_store(func, inst) {
            // Each of these already names a version of memory all on its own,
            // function wide, and so doesn't need an additional extent token.
            LastStore::NoStore | LastStore::Inst(_) => NULL_EXTENT,

            // This one, on the other hand, only names a version of memory
            // relative to the control-flow join that lost track of it.
            LastStore::Unknown => {
                debug_assert_ne!(self.extent, NULL_EXTENT);
                func.dfg
                    .insts[inst]
                    .alias_region(&func.dfg)
                    .map_or(self.extent, |region| self.region_extents[region])
            }
        }
    }
