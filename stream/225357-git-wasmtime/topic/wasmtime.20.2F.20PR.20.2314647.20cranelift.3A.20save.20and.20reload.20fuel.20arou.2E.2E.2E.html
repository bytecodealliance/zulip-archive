ctiller opened PR #14647 from ctiller:fix/epoch-check-fuel to bytecodealliance:main:

When both consume_fuel and epoch_interruption are enabled, FuncEnvironment::epoch_check_full emits a conditional call to the new_epoch libcall at function entry and loop headers. Although fuel_check flushes buffered fuel into the SSA variable self.fuel_var immediately beforehand, epoch_check_full did not store self.fuel_var back to VMStoreContext::fuel_consumed before invoking new_epoch or reload it afterwards.

Consequently, if the epoch deadline callback inspected store.get_fuel() or trapped (UpdateDeadline::Interrupt / Err(...)), all fuel consumed since the last store synchronization was missing from the Store.

Save self.fuel_var before calling new_epoch and reload self.fuel_var afterwards when consume_fuel is enabled.
