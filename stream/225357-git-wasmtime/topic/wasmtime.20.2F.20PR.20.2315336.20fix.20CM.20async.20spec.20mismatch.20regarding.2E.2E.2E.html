dicej opened PR #15336 from dicej:fix-barging-ahead-of-pending-tasks to bytecodealliance:main:

The spec says that new tasks are not allowed to "barge ahead" of earlier calls which have been queued due to backpressure, i.e. they need to wait until the queued calls have started before they can run.

The solution here is to maintain a count of those calls (ConcurrentInstanceState::pending_start_count) and add a was_pending field to GuestCallKind::StartImplicit. When creating a new call, we set was_pending to false. Then, if backpressure requires us to queue the call, we set was_pending to true and increment pending_start_count. GuestCall::is_ready now checks both was_pending and pending_start_count (in addition to backpressure, etc.) to determine whether a task can start or needs to be queued, per the spec. Finally, any time we start or cancel a task with was_pending set to true, we decrement pending_start_count.

Claude found the bug and wrote the test case. I wrote the fix independently. I take responsibility for all of it.
