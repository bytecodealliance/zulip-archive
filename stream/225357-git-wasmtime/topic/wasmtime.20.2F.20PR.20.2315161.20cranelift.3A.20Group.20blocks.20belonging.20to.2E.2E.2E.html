Amanieu commented on PR #15161:

Regarding the DFS idea: this is actually something that I used to do in my compiler. However it turns out that this doesn't work in all cases.

Consider the test case in blockorder.rs: the only DFS choice here is whether you visit 2 or 3 first. This means that the only 2 RPOs that it can produce are:

  • 0, 1, 3, 5, 2, 4, 6
  • 0, 1, 2, 4, 3, 5, 6

Regarding complexity, this pass is linear and uses O(blocks) time and memory. The stack size is the maximum loop depth, and the total set of Items are one for each block and one for each loop.
