cfallin opened PR #14444 from cfallin:wasi-nn-ci-remove to bytecodealliance:main:

This is a response to a high frequency of recent CI failures, all stemming from the unreliability of the package sources for wasi-nn dependencies (e.g. OpenVINO) or the tests themselves. See these failures in recent times:

  • 404 on package repository (parcel.pyke.io)
  • and another
  • and another
  • DNS failure to resolve download.01.org
  • an illegal-instruction error when running OpenVINO on Windows

With our security release on 2026-09-24, these repeated errors caused serious delays in the process to release fixes to tier-1 features. Since wasi-nn is considered a tier-3 feature, it needs to abide by this provision in the tier documentation:

Inclusion of a feature does not impose unnecessary maintenance
overhead on other components/features.

We aren't at this time choosing to remove wasi-nn itself, but unfortunately it seems we can no longer reliably test it in CI in a way that avoids negative impacts.

Note also that the test itself is already excluded from the "required tests" filter on release branches for v36, v48, and v49, in response to these failures. We likely shouldn't keep it in-tree if we just comment it out in each release branch.
