V0ldek opened PR #15046 from V0ldek:v0ldek/remove-runtime-memory-creator to bytecodealliance:main:

As discussed in #14989, this PR flattens the memory creation path by making the internals use the same trait as the public API (MemoryCreator).

The biggest change is the public API change for MemoryCreator, where it now receives all parameters to new_memory packaged in MemoryRequest. This allows us to expose all the previous configuration parameters that implementations require for correctness, while hiding some internal tunables that are used in the DefaultMemoryCreator. The public API surface is slightly increased to include a MemoryKind enum that notifies the creator whether it's creating a standard linear memory or a GC heap, in case implementations want to serve these two differently. I also added docs for telling people how GC heaps differ from linear memory.

The actual code changes are mostly mechanical:

  • the MemoryRequest exposes the parameters as public accessors, plus pub(crate) ones for the internal parameters
  • RuntimeMemoryCreator trait is gone and everything that refered to it refers to MemoryCreator instead
  • the MemoryCreatorProxy became dead code and was removed.

Added one test for the GC creation path to ensure we don't issue multiple heap requests to the creator once one was created for a store.

The C and C++ APIs were updated to match the signatures of Rust.
