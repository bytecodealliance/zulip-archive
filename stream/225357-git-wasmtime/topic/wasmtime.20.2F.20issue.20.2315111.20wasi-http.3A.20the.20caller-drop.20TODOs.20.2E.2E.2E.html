Wasmtime GitHub notifications bot (Nov 02 2026 at 11:45):

xia-chao opened issue #15111:

handler.rs has two TODOs (p3, p2) suggesting we expire a request when the caller drops the response future.

I tried that in #14625 and it was closed: it breaks worker reuse. Two cases that pass on main and failed with the change:

  • p2: the caller drops after the guest has already responded; expiring the request ends up killing the reused worker and truncating an unrelated in-flight response.
  • p3: every abandoned request retires its instance, so instances stop being reused.

Reproducers from @rvolosatovs's review branch: https://github.com/rvolosatovs/wasmtime/blob/6131efe89c969c471a8796af65607e0846d07707/crates/wasi-http/tests/all/pr14625.rs (they pass on main).

So the TODOs point at a behavior that conflicts with what the code does today. Should they be removed, or reworded to say "revisit once task cancellation (#11833) is available"?

cc @rvolosatovs
