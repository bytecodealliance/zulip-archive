Topic: wasmtime / issue #14859 The wasmtime CLI doesn't support ...

Wasmtime GitHub notifications bot (Oct 19 2026 at 20:46):

jrandolf opened issue #14859:

wasmtime run and wasmtime serve never call add_named_to_linker, so a component with a labelled WASI import, e.g. import env2: wasi:cli/environment@0.3.2; or a labelled wasi:http/client, fails to link:

component imports instance `env2`, but a matching implementation was not found in the linker

Labelled exports don't work either: export h: wasi:http/handler@0.3.0 under serve fails with a misleading no exported instance named 'wasi:http/incoming-handler@0.2.12', and a labelled wasi:cli/run export under run with no exported instance named 'wasi:cli/run@0.2.12'.

Some possible options:

  • bind every labelled WASI import to the default context (maybe behind something like -S named-imports),
  • later, allow per-label configuration (--env/--dir),
  • for exports, fall back to the unique export that implements the expected interface.

Is this something the CLI should support, and if so, which direction would you prefer?

alexcrichton commented on issue #14859:

Personally I'd err on the side of not doing anything here and just leaving this open. It's probably a nontrivial bit of infrastructure to add better error messages here at minimum and it's not clear that it's necessarily worth it just yet. I don't think it makes sense to just bind to the default context because that sort of defeats the purpose of named imports in the first place
