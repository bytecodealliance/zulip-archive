This removes two methods in cranelift-entity whose unsafe code has no callers left in the workspace:

  • PrimaryMap::get_raw_mut — only referenced by its own unit test and by an equally unused wrapper in wasmtime-environ (TryPrimaryMap::get_raw_mut); both are removed. This also addresses bjorn3's point on the earlier revision: the wrapping_add there had no in-bounds guarantee to lean on, so the sound thing is for the method not to exist.
  • PrimaryMap::into_boxed_slice — only used by the BoxedSlice tests; they now construct BoxedSlice directly through its pub(crate) constructor.

Motivation: reducing the unsafe surface where the code is dead anyway. There is no bug behind this — the methods were not called, they just carried unsafe contracts for no benefit. This kind of unsafe-reduction is also the class of change covered by Google's Patch Rewards program for OSS-Fuzz projects (Tier 2 hardening), which is part of why I went looking for it.

An earlier version of this PR also added #![forbid(unsafe_code)] to the crate; I removed that again after fitzgen's review, since the crate may legitimately want unsafe in the future.

Testing: cargo test -p cranelift-entity — 59 unit tests and 2 doc tests pass; cargo check -p wasmtime-environ passes.

Open question from the review thread: BoxedSlice itself now has no users and cannot be constructed from outside the crate. I'm happy to remove it in this PR too if the maintainers want that.
