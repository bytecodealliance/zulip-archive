Add mid-end optimization rules:

  • (~x | y) ^ x --> ~(x & y)
  • (~x OP y) ^ (~y OP x) --> x ^ y, where OP = {&, |}
  • (~x | y) & (~y | x) --> ~(x ^ y)
  • max(x, y) OP min(x, y) --> x OP y, where OP = {&, |, ^}
  • max(~x, ~y) --> ~min(x, y)
  • min(~x, ~y) --> ~max(x, y)
  • ~max(~x, y) --> min(x, ~y)
  • ~min(~x, y) --> max(x, ~y)
  • -(x & y) + x --> x & ~y
  • (~x & y) + (~y & x) --> x ^ y
  • (-x) - (~x) --> 1
  • ~x + C --> (C - 1) - x
  • (x + C) ^ -1 --> (-(C + 1)) - x
  • (x | C) - C --> x & ~C
  • (x | C) ^ (y | C) --> (x ^ y) & ~C
  • (x | C) ^ (y ^ C) --> (x & ~C) ^ y
  • (x << 1) * C --> x * (2 * C)
  • ~rotl(~x, k) --> rotl(x, k)
  • ~rotr(~x, k) --> rotr(x, k)
  • (x << 1) == x --> x == 0
  • (x >>u 1) == x --> x == 0
  • (~x & y) == y --> (x & y) == 0
  • ~x == (~x | y) --> (x & y) == 0
  • umax(x, y) OP 0 --> (x | y) OP 0, where OP = {==, !=}
  • umax(x, y) OP umin(x, y) --> x OP y, where OP = {==, !=}
  • (x >=s y) & (y >=s x) --> x == y
  • (x >=u y) & (y >=u x) --> x == y
  • select(c, x, y) == select(c, y, x) --> x == y
  • select(x == 0, -x, x) --> x, and corresponding x != 0
  • select(x == 0, 0, x OP y) --> x OP y, where OP = {&, *}, and corresponding x != 0
  • ~select(c, C1, C2) --> select(c, ~C1, ~C2)
  • -select(c, C1, C2) --> select(c, -C1, -C2)

Thanks!

Wasmtime GitHub notifications bot (Oct 23 2026 at 19:15):

:speech_balloon: myunbin created PR review comment:

@cfallin

I believe it's because of the rule ~x + C → (C - 1) - x.

When C=1, both rules match:

  • ~x + 1 → (1 - 1) - x → 0 - x (added rule in this pr)
  • ~x + 1 → -x (existing one)

The cost model assigns both candidates as 4: ineg(4) and iconst(1) - isub(3), therefore tie.
Maybe the tie breaker chooses 0 - x afterward.
