The ONNX backend can decode only f32 input tensors. For other types, compute returns UnsupportedTensorType, so models that take i64 token IDs cannot run.

This change decodes input tensors of all seven wasi-nn tensor types with one generic helper. For f16 and bf16, it turns on the half feature of ort and adds half as a dependency. half 2.4.1 is already in Cargo.lock, so no new crate comes in. The setup step now also accepts models with f16 and bf16 tensors. The change also removes bytes_to_f32_vec, which has no users now.

Outputs are still f32 only. That can be a follow-up.

CI does not run the wasi-nn tests. To run the new unit tests:

cargo test -p wasmtime-wasi-nn --features onnx-download --lib
