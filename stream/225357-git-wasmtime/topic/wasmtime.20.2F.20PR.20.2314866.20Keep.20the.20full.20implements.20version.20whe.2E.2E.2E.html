jrandolf opened PR #14866 from jrandolf:implements-canonical-version to bytecodealliance:main:

With canonical names enabled, (implements "a:b/c@1") (version-suffix ".2.3") was recorded as just a:b/c@1. So ComponentExtern::implements reported a truncated name, and is_implements didn't match any version of the interface, which made bindgen!'s named_imports and the WASI add_named_to_linker silently skip such imports. This records the full a:b/c@1.2.3, using wasmparser's full_implements().

Root import names had the same problem: an import of a:b/c@1 with suffix .2.3 was looked up in the Linker as a:b/c@1, which never matches a host definition like a:b/c@1.2.3. Imports now use the full name too. Lookups inside the component still use the short canonical name.

Exports with a version suffix still use the short name (get_export("a:b/c@1.2.3") doesn't find them), and so do interface-named exports inside instance and component types. Fixing those is a larger change, so I left them for a follow-up.

Closes #14854
