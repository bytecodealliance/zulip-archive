A few small things found while looking at map<K, V>:

  • The Val::Map docs said duplicate keys follow "last value wins" semantics, but Val::Map keeps every entry in order, duplicates included (only lifting into a typed HashMap deduplicates). This documents that, along with how map equality behaves.
  • Adds Type::unwrap_map to match the other unwrap_* accessors.
  • Mentions the :map: emoji and the default in the config and CLI docs, like the neighboring options.
