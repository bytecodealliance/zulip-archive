Empty body writes have been shown to be a vector for unmetered heap growth in some http implementations. Drop these writes while still maintaining behavior that guest's may rely on.

For p2 BodyWriteStream, empty writes are dropped but Err(StreamError::Closed) is still returned if the underlying writer is closed.

For p3 {Limited,Unlimited}GuestBodyConsumer emtpy writes will maintain the same behavior of waiting until there is capacity to write (Ready) but at the time that we would have previously written the empty buffer over channels, we just mark the chunk as completed without being sent avoiding potential unbound memory growth channels in backing implementations, including hyper/h2.

Neither p2 or p3 wasi:http specifies behavior for empty body writes, and body contents are a byte stream with no defined mapping onto HTTP framing, so skipping them leaves the transmitted body unchanged:

  • p2: wasi:io output-stream.write only requires that contents fit the check-write permit and that closed be returned if the stream has closed. An empty write now returns Ok(()), or closed once the body's receiver is gone.
  • p3: the Component Model treats a zero-length stream.write as a readiness probe whose completion is "allowed (but not required) to wait ... until the other end is 'ready'". An empty write now waits for channel capacity, as before, and completes with 0 items without forwarding anything.
