dicej opened PR #15350 from dicej:fix-new-transmit-scope-bug to bytecodealliance:main:

This fixes incorrect code in StoreContextMut::new_transmit. Specifically, the dropped variable that was moved into a closure and then again into an async block was moved by _value_, whereas I meant for it to be moved by reference the same way an AsyncFnMut would do it; i.e. I didn't think through the semantics of the nested closures. Consequently, each returned future got its own copy, so the value didn't persist across closure calls as intended.

The solution is to make variable a field in the producer state (which I've converted from a tuple to a struct for better readability) so that it persists as intended.

The issue was found, and the new tests (mostly) written, by Claude. I wrote the fix independently and take responsibility for both.
