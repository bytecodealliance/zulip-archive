alexcrichton opened PR #14782 from alexcrichton:refactor-globals to bytecodealliance:main:

This commit refactors the representation of VMGlobalDefinition which for the longest time has been [u8; 16] and IIRC predates the addition of union to Rust. The previous implementation had a bug where funcref fields were loaded/stored as *mut VMFuncRef but this is not compatible with provenance and Pulley. Instead globals needed to use Option<VmPtr<VMFuncRef>>, and instead of just fixing this one case for globals I've refactored globals to use a union.

The change here reflects the internal representation of wasm globals and how Cranelift accesses them. Documentation is additionally added indicating that some fields are little-endian and some are native-endian. The field type for funcref is Option<VmPtr<_>> to resolve the provenance issue as well.
