Fixes #14699.

Testing x % c == 0 currently computes the whole quotient and multiplies back to recover the remainder, even though only the zero test is used. On x86-64 that is a mull plus shift/imul sequence; LLVM emits a single multiply and compare for the same test.

The fold is not expressible today for a structural reason. urem and srem are modelled as skeleton instructions because they can trap, and a skeleton instruction's result is replaced by its rewrite before the icmp consuming it is visited, so a simplify rule can never see the icmp(urem x, c) pair. A remainder by a non-zero constant divisor cannot trap (srem only traps on a zero divisor and yields 0 for INT_MIN % -1), so those nodes are now pure and the existing remainder rewrites move from simplify_skeleton to simplify behind new urem_value/srem_value extractors. The constant folds subsume so they are not competed away by the magic-number sequences, and the extraction cost model prices integer division above the sequences that replace it.

The new rules cover signed and unsigned remainders, eq/ne, odd and even divisors, and 8/16/32/64-bit widths. Even divisors use a rotate to fold the low-bit requirement into the same compare, and signed tests add a bias so negative multiples land in the same range.

egraph/divisibility.clif shows the folded shape for each combination, and runtests/divisibility.clif checks the folded test against the interpreter and the host target.

Trap behaviour is unchanged: urem x, 0 still emits divl, srem x, -1 still emits the checked idiv sequence, and urem x, 8 still becomes band.

A function that only performs a divisibility test compiles from 64 bytes to 29 bytes. Separately, a 500M-iteration wasm loop that counts multiples of 7 runs in 301 ms instead of 491 ms, minimum of five runs. Both numbers were measured with the initial revision of this branch; the later fixes only affect signed remainders and constant folding, which that unsigned loop does not use.

The ISLE verifier passes for opt-fast and opt, the latter being what CI runs. No specifications are provided for the magic-number helpers, so the rules using them are tagged TODO and are not formally verified yet. u64_shl is tagged because its existing specification uses a match clause on a term the verifier treats as non-partial, and i64_is_any_sign_power_of_two because it is defined by priority-ordered rules the verifier does not negate. The tags are added here so the verification run can proceed.

Checks run: cargo test -p cranelift-tools --test filetests, cargo test -p cranelift-codegen, cargo clippy -p cranelift-codegen --all-targets -- -D warnings, rustfmt --check, and cranelift/isle/veri/verify.sh on opt-fast and opt.

losewayy edited PR #14879:

Fixes #14699.

This adds constant-divisibility tests for x % c == 0 and x % c != 0, using precomputed multipliers, bit operations and comparisons instead of computing the full remainder. Unsigned even divisors use a rotate; signed tests use a bias and check the low bits separately.

The rules stay in simplify_skeleton, alongside the existing remainder optimizations. Before forward rewriting, a use scan records remainders whose results are only compared with zero. This is needed because the skeleton pass visits the remainder before its comparison consumers. The set is rebuilt for each pass and is only consulted when rewriting a remainder. If another use needs the actual remainder, the normal remainder calculation is retained.

The implementation handles signed and unsigned 8-, 16-, 32- and 64-bit integers. Existing power-of-two handling is retained. Zero divisors keep their trapping operations, and signed MIN % -1 retains its zero result.

Validation on Windows x86-64: 209 codegen library tests and 86 filetests passed, covering the egraph suite and the relevant division/remainder runtime files. Added cases include i8 comparisons with zero on either side, zero divisors in optimized IR, signed -1 with MIN inputs, MIN divisors, mixed uses and block arguments. Division-by-zero was checked in optimized IR, not executed in the runtime harness. Crate formatting and git diff --check pass.

The current VeriISLE configuration verifies simplify; it does not support these simplify_skeleton rules.
