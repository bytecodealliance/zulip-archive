jrandolf opened PR #14801 from jrandolf:cm-map-default to bytecodealliance:main:

WASI 0.3.1 adopted the map<K, V> type, which means runtimes need to support it to be compatible with WASI 0.3.1 and later (see ComponentModelFeatures.md). docs/stability-wasm-proposals.md already lists every criterion as met for map, so this flips the default and moves it into the on-by-default table.

Without this a component that uses map fails to load unless -W component-model-map is passed.

I don't believe that map<K, V> is suitable to enable just yet. I've filed a few issues:

  • https://github.com/bytecodealliance/wasmtime/issues/14813
  • https://github.com/bytecodealliance/wasmtime/issues/14812
  • https://github.com/bytecodealliance/wasmtime/issues/14811
  • https://github.com/bytecodealliance/wasmtime/issues/14810

These are the most serious issues I found in a review locally, but tehre's a litany of possible issues with bindgen! as well in terms of no-std compat, the limitations placed on the current impls, the lack of support for types in the current impls (e.g. no BTreeMap, no "just give me the list", etc).

Overall I do not personally feel that this is ready to just turn it on.
