macovedj opened PR #14490 from macovedj:subtask-cancel-lifetime to bytecodealliance:main:

A guest can request asynchronous cancellation and then attempt to drop
the subtask before cancellation finishes. Previously, subtask.cancel
immediately marked the host task as done, allowing that drop even when
cancellation returned BLOCKED.

This can remove a task entry that the completion worker still references.
If another host call reuses the slot, the old completion can report
RETURN_CANCELLED for the new task, even though it was never cancelled.

This PR introduces CalleeCancelling to preserve the task entry while completion
processing is pending and rejects subtask.drop until that processing has
finished and the terminal event has been delivered.
