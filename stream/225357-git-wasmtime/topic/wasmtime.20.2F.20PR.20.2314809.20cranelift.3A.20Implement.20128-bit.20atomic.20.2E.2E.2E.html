Unfortunately, it is currently not possible to implement this in ISLE. I tried, and failed miserably. The implementation for 64-bit can be done in ISLE because it can hardcode two physical GPRs - r0 and r1 - which are excluded from regalloc. This is not the case with the VRs, which we are using for the 128-bit integers, so we end up violating SSA rules if we attempt to implement this in ISLE (previous attempt: https://github.com/Gelbpunkt/wasmtime/commit/124d0212ff470557cf5b6fc2aa107daa1d878edc).

On a technical level: We use a CAS loop for this, just like with the 64-bit atomics. It is actually quite straightforward to implement, however there's a small caveat: We cannot use the vector min/max operations prior to z17, so we need to implement a fallback for the baseline if VXRS_EXT3 is not available.

I've tested this in qemu-user with and without VXRS_EXT3, and the runtest passes in both environments.

Unfortunately, it is currently not possible to implement this in ISLE. I tried, and failed miserably. The implementation for 64-bit can be done in ISLE because it can hardcode two physical GPRs - r0 and r1 - which are excluded from regalloc. This is not the case with the VRs, which we are using for the 128-bit integers, so we end up violating SSA rules if we attempt to implement this in ISLE (previous attempt: https://github.com/Gelbpunkt/wasmtime/commit/124d0212ff470557cf5b6fc2aa107daa1d878edc).

I think it might be possible to extend the Loop construct with a list of temporary registers that are allocated as fixed early-def, and then use registers from that list as scratch registers inside the loop.

However, I'm not sure it's really worth the effort at this point. I added Loop primarily to allow more concise encoding of the various sub-word CAS loops. For the i128 case, implementing it in the emitter seems straightforward enough.

Generally, this implementation looks good to me, but I think we could be more frugal with scratch register use, see inline comments.

I don't think we need scratch1 or scratch2 here. It should be possible to only use rd to hold any scratch VR values, something along the lines of:

rd <- mem
scratch3 <- rd

loop:
  case XChg:
    scratch4 <- rn

  case arith:
    rd <- Op(rd, rn)
    scratch4 <- rd

  case min/max fallback:
    if (VecInt128[US]CmpHi(tmp: rd, [rd|rn], [rn|rd]))
      scratch4 <- rn
    else
      scratch4 <- scratch3

  scratch3 <- AtomicCas128(scratch3, scratch4)
  rd <- scratch3

  if cas-failed goto loop

Multiple assignments to rd should be fine as it is marked as early-def (and they happen with your version already anyway).
