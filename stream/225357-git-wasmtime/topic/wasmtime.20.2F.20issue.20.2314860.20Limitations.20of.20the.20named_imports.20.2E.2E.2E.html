jrandolf opened issue #14860:

A few limitations of the named_imports lookup API generated by bindgen! (and used by the WASI crates):

  • The lookup only receives the import name. external-id, which the spec describes as telling the host how to supply an import, is never passed along. Passing the ComponentExtern would cover it.
  • The lookup can't decline an import: returning Err aborts linking, so an embedder can't leave a particular label to be defined some other way. Something like Result<Option<Id>> would allow that.
  • Tracing spans for calls through different labels are identical (module="store" function="get"), with no label or id.
  • Per-function rule keys are inconsistent: labelled imports need interface keys ("foo:foo/store.get") while labelled exports need label keys ("c.greet"), and with: { "a": .. } for a label reports a misleading "not referenced in the target world" error.
