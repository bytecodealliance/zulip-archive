fitzgen opened PR #15034 from fitzgen:lazy-lenders to bytecodealliance:main:

This commit introduces a lazy_lenders buffer on VMStoreContext. When we need to push a lender for a resource borrow, but haven't forced the lazy thread context yet, we push to lazy_landers. This avoids forcing the lazy thread context, like we previously did. Each VMDeferredThread keeps a watermark of the lazy_lenders length upon construction so that, when we do something that does force the lazy thread context, we can partition lazy_lenders by each thread context that is responsible for those borrows.

This does not change what is inlined in Wasm code or what is done in libcalls. In the inline exit-sync-call fast path, we bail out to the host when there are lazy lends to be undone. The host libcall still takes care to avoid forcing the VMDeferredThread right before we exit the call in this case.

Follow up commits will move a bunch of this work inline into the adapters, but I wanted to keep this introduction of lazy_lenders as small as I could.

Even so, this is a significant speedup for cm-online-stats, our adapter-call-heavy Sightglass benchmark:
