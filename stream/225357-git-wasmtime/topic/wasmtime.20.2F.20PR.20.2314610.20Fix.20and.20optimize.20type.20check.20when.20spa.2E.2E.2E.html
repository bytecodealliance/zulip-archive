This commit adjusts the type-check of the function passed to thread.new-indirect in a few ways:

  • The type-check is now more optimal -- previously a new FuncType was created which requires taking engine locks, not a fast path.
  • The type-check now checks against the type immediate on the thread.new-indirect instruction.

The latter part here is intended to fix spawns with types that are structurally-the-same-but-distinct, basically handling the GC-introduced type hierarchy for functions and interning. Now a thread.new-indirect intrinsic accepts exactly only functions of the type that it was annotated with. New intrinsics can be created if necessary for other types within a guest.
