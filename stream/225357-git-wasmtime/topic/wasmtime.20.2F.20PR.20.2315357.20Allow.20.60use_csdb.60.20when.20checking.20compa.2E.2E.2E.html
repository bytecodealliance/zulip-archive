andrewl6097 opened PR #15357 from andrewl6097:aarch64-use-csdb-native to bytecodealliance:main:

use_csdb was added in #12932 so embedders could opt back into csdb on aarch64, but Engine::check_compatible_with_native_host doesn't know about it. With it enabled on an aarch64 host, Module::new and loading a precompiled module both fail with don't know how to test for target-specific flag "use_csdb" at runtime, so the setting docs/security.md recommends can't be used for native code.

CSDB is encoded in the hint space and runs as a NOP on CPUs that don't implement it, so this adds it next to use_bti among the aarch64 flags that need no detection.

The new test in tests/all/module.rs runs only on aarch64. For both use_bti and use_csdb, it compiles a module with a call_indirect (a Spectre-guarded table access) and a br_table (a jump table), which are the two places use_csdb emits csdb. It then calls the module through both paths, and serializes and deserializes it. I've only been able to run the module itself on x86-64 without the flags, so the aarch64 run is up to CI.

Closes #(issue)

I'd like this backported to release-51.0.0 before 51.0.0. The commit cherry-picks onto it without conflicts.
