Wasmtime GitHub notifications bot (Nov 13 2026 at 19:14):

alexcrichton opened issue #15267:

With the custom-page-sizes proposal enabled, WasmCoreDump::serialize writes a core dump that doesn't match the guest's memories:

(module
  (memory $small 5001 (pagesize 1))
  (memory $tiny 100 (pagesize 1))
  (data (memory $small) (i32.const 0) "head")
  (data (memory $small) (i32.const 4090) "across-the-boundary")
  (data (memory $small) (i32.const 4990) "tail-bytes")
  (data (memory $tiny) (i32.const 10) "tiny-data")
  (func (export "trap") unreachable))

$ wasmtime run -W custom-page-sizes=y -D coredump=out.core --invoke trap cps.wat
$ wasm-tools print out.core
(module
  ...
  (memory (;0;) 5001)
  (memory (;1;) 100)
  (data (;0;) (i32.const 0) "head\00\00...\00across")
  ...
)

There are two problems here:

  • Both memories have the wrong page size.
  • Data past the last full 4096-byte chunk is missing.
