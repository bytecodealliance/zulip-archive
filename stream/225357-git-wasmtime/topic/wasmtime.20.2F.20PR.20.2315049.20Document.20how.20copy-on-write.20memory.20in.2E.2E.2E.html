yadava5 opened PR #15049 from yadava5:docs-fuel-cow-determinism to bytecodealliance:main:

Closes #14331.

As discussed in the issue, this documents that copy-on-write memory init changes how much fuel instantiation consumes from host to host, and that disabling memory_init_cow makes it the same everywhere. The note goes on Config::consume_fuel, with a pointer from Config::memory_init_cow, the "Deterministic Fuel" section, and the deterministic execution guide.

I measured it with the module from the issue (one memory, a data segment of 5 bytes) on GitHub's runners:

host page size CoW, Module::new CoW, deserialize_file no CoW
Linux x86_64 4 KiB 0 0 7
Linux aarch64 4 KiB 0 0 7
macOS x86_64 4 KiB 4097 0 7
macOS aarch64 16 KiB 16385 0 7
Windows x86_64 4 KiB 4097 4097 7

The probe is here.

One thing I noticed while measuring: when CoW is enabled but can't be used, the copy is charged for the whole image rounded up to a page, so 5 bytes cost a full page of fuel. I kept that out of this PR since it's a behavior change, but happy to look at it separately if it's worth changing.

I used Claude Code to measure the fuel numbers and check the doc links.
