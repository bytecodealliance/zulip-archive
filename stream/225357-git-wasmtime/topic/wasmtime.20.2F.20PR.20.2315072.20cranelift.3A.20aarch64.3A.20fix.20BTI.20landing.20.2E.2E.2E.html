NicolasStigler opened PR #15072 from NicolasStigler:fix/aarch64-bti-indirect-targets to bytecodealliance:main:

Fixes #14938

Why

With BTI and pointer authentication enabled on AArch64, several indirect control-flow paths could trap with an illegal instruction. The affected cases include br_table defaults, exception-handler targets, indirect tail calls, and tail-convention prologues using paciaz/pacibz.

What changed

  • Mark br_table defaults and exception-handler targets as indirect branch targets so they receive bti j.
  • Emit bti c before paciaz/pacibz where needed.
  • Route indirect tail calls through x16 before branching.
  • Add and update AArch64 filetests and runtime configurations for BTI and pointer authentication.
