SilverMira opened PR #14376 from SilverMira:main to bytecodealliance:main:

closes: issue #14366

Through some trait and lifetime magic, it is possible to effectively specify a Send bound on the unnamed Future returned by AsyncFnOnce on stable.

This commit uses said magic and changes AccessorTask from a manually implemented trait into an async closure returning a Future that is Send. Users can now pass async move |accessor| { ... } into Accessor::spawn and friends directly, skipping boilerplate of creating a struct and implementing AccessorTask manually.

Additionally, it is no longer intended for users to manually implement AccessorTask, as implementing the trait now requires Self to also implement AsyncFnOnce, which is unstable.

All occurrences that manually implement AccessorTask within the repo is updated to just use an async closure.

I have verified that rustc is happy with cargo check -p wasmtime-wasi-tls as recommended in #14366, in both the nightly trait solver and stable trait solver via RUSTFLAGS=-Znext-solver=coherence.

This is a breaking change of course.
