This adds map support where Wasmtime prints and parses WAVE values, using wasm-tools 1.263.0, now on main via #15097:

  • wasmtime run --invoke, Val::to_wave and Val::from_wave print and parse maps as {key: value, ...} (bytecodealliance/wasm-tools#2782). WAVE merges duplicate keys, keeping the last value.
  • map-types.wast uses the existing map.const support to check that guest-returned maps and map arguments retain duplicate keys. This covers the duplicate-keys test that #14834 dropped, as suggested there.
$ wasmtime run -W component-model-map --invoke 'echo({3: 4, 1: 2, 3: 5})' component-map.wat
{3: 5, 1: 2}

jrandolf edited PR #14843:

Component maps are currently unsupported by Wasmtime's WAVE integration. Implement the wasm-wave map traits for component::Type and component::Val in crates/wasmtime/src/runtime/wave/component.rs, enabling Val::to_wave, Val::from_wave, and wasmtime run --invoke to handle maps through the existing parsing and display helpers.

WAVE merges duplicate keys, keeping the last value:

$ wasmtime run -W component-model-map --invoke 'echo({3: 4, 1: 2, 3: 5})' tests/all/cli_tests/component-map.wat
{3: 5, 1: 2}

CLI tests cover empty maps, map arguments and results, and duplicate keys. WAST tests use the existing map.const support to check that Val::Map retains duplicate entries when lowering arguments and lifting results.

Closes #14811
