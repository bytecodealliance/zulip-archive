GC array accesses previously would compute a pointer to the last byte of the object being addresses, then subtract backwards from there. With spectre mitigations turned on, however, this means that a faulting access would underflow from 0 to the high end of the address space. While this is guaranteed to fault still it's an unrecognized address in Wasmtime's defense-in-depth "is this a faultable address check". This means that when this defense in-depth-check fired it would erroneously consider the faulting access invalid and abort the process instead of handling the trap as usual.

The fix here is to refactor methods a bit further to factor in this "calculate last byte, bounds check, then go backwards for the pointer" check. Now out-of-bounds accesses load from null, like all other out of bounds accesses.
