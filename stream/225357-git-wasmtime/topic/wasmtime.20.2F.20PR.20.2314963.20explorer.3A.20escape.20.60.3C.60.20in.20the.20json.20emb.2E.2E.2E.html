wasmtime explore writes the annotated WAT, disassembly and CLIF into the generated page as JSON inside <script> elements, using serde_json::to_string. That serializer leaves < alone, so any string copied out of the module (an export or import name, a data segment as printed by wasmprinter, a function name from the name section) is emitted verbatim. A module containing </script> ends the script element early, and whatever follows is parsed as markup and script by the browser the developer opens the page in.

This routes the three JSON blobs through a small helper that replaces < with the equivalent JSON escape \u003c. The JavaScript parser decodes it back to the same string, so the rendered WAT and names are unchanged. The new unit test generates a page from a module whose export name and data segment contain </script> and checks that only the page's own two closing tags remain; it fails before this change and passes after.

Tested with cargo test -p wasmtime-internal-explorer --lib, cargo fmt --all -- --check and cargo clippy -p wasmtime-internal-explorer --all-targets.
