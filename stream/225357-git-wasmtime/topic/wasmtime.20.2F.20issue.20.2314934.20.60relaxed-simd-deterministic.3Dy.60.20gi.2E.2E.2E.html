davidads-Humanis-AIs opened issue #14934:

The Wasm 3.0 spec says for relaxed_madd: "In the deterministic profile, the unfused behaviour is used." With relaxed-simd-deterministic=y, Wasmtime returns the fused result instead.

Test Case

madd.wat:

(module
  (func (export "madd64") (param i64 i64 i64) (result i64)
    (i64x2.extract_lane 0
      (f64x2.relaxed_madd
        (f64x2.splat (f64.reinterpret_i64 (local.get 0)))
        (f64x2.splat (f64.reinterpret_i64 (local.get 1)))
        (f64x2.splat (f64.neg (f64.reinterpret_i64 (local.get 2))))))))

Steps to Reproduce

wasmtime run -W relaxed-simd=y,relaxed-simd-deterministic=y \
  --invoke madd64 madd.wat \
  4607182418804211712 4607182418791628800 4607182418800017408

The arguments are a = 1 + 2^-30, b = 1 - 2^-30, c = 1, and the function computes a*b - c. The exact product 1 - 2^-60 rounds to 1, so the unfused result is 0 and the fused one is -2^-60.

Expected Results

0

Actual Results

-4886405595696988160 (f64 bits 0xbc30000000000000, i.e. -2^-60)

Versions and Environment

Wasmtime version or commit: 50.0.0 (ebe5e8df1 2026-10-20)

Operating system: Linux

Architecture: x86_64

Extra Info

The same happens with -Ccranelift-has_fma=false. In that case relaxed-simd-deterministic=n gives 0 (fmul + fadd), but =y still gives -2^-60 through the fma libcall. f32x4.relaxed_madd and both relaxed_nmadds behave the same way with analogous inputs. The lowering is fma_f32x4/fma_f64x2 in crates/cranelift/src/func_environ.rs, which has the comment // Deterministic semantics are "fused multiply and add".
