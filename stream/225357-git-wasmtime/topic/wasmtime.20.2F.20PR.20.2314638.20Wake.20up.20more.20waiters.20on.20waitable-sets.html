alexcrichton opened PR #14638 from alexcrichton:wake-more-waiters to bytecodealliance:main:

When an event is delivered to a waitable set technically any thread in that set is candidate for receiving the event, but prior to this commit Wasmtime would only ever deliver the event to one arbitrary thread in the set. This caused issues when that thread cannot run due to the instance's lock being held, meaning that other candidate threads couldn't run to completion and actually get the event. This commit handles this situation by waking up other threads in in this situation. Only one thread will still get the event, and others go back to sleep if it's stolen.
