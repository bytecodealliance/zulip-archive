simolus3 opened PR #14605 from simolus3:gc-page-size to bytecodealliance:main:

This adds the gc_heap_page_size_log2 option, which can be used to control the page size of the memory used for GC allocations.

Matching an existing assertion on memory page sizes, the only allowed values are 0 (1 byte pages) and 16 (64k pages). Exposing this uncovered a few issues related to how memory growth is computed (which didn't take alignment into account and could thus grow memory by an incorrect amount, something that 64k pages hide).

Closes https://github.com/bytecodealliance/wasmtime/issues/14523.
