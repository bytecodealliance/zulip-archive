jrandolf opened PR #14837 from jrandolf:bindgen-map-path to bytecodealliance:main:

bindgen! generated std::collections::HashMap<K, V> for WIT maps, but the ComponentType/Lift/Lower impls are on Wasmtime's internal HashMap, which is hashbrown::HashMap when the std feature is disabled, so any WIT using map failed to compile in that configuration. This re-exports that type from component::__internal and uses it in generated code like Vec and String already are.

To cover this in CI, the min-platform example gains a small world using a map, since that's the build that runs without std (it fails with cannot find module or crate std without this change). I'm not attached to that location if there's a better place for a no_std bindgen check.

This is based on #14834; only the last commit is new.

Closes #14830
