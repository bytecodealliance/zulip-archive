wraitii opened PR #15201 from wraitii:fix/licm-separate-loops to bytecodealliance:main:

The elaborator’s loop stack can include a loop that dominates the current block but has already exited. Treating the stack as a nested loop chain can hoist instructions across that unrelated loop, extending live ranges without reducing repeated work.

Pseudocode example of the issue:

hot = n
do:
    hot -= 1
while hot != 0

cold = n
do:
    step = unsigned(n) >> (n & 63)
    cold -= step
while cold != 0

Incorrect placement before the fix:

step = unsigned(n) >> (n & 63)  // hoisted across the unrelated hot loop
hot = n
do:
    hot -= 1
while hot != 0

cold = n
do:
    cold -= step
while cold != 0

The fix places step after the hot loop, before the cold loop. The code remains correct in both cases but the generation is significantly worse, especially as this increases register pressure.
