Motivation

Active element segments targeting imported tables currently materialize every native function-reference record at instantiation. Large linked modules can initialize many such slots that the embedding never reads or calls.

Change

Retain eligible active-segment function indices in immutable module metadata and record bounded source/range bindings on the table. Existing lazy reads materialize references from the contributing instance when needed. Tagged explicit writes, including nulls, take precedence; later segments override earlier ranges. Unsupported segment forms and deferred-history overflow retain eager initialization.

Bounds checks, segment order and fuel charges stay at the original startup boundary. The Store retains contributing instances even when a later segment or start function traps. Pooled table replacement discards the deferred bindings. Metadata allocation failure declines deferral before changing table contents.

The new fallible internal initializer opts out of host-call hooks, matching the previous infallible ref_func sequence. Other builtin, host-function and component hooks retain their existing behavior. This requires a small internal flag through the trap wrapper; no public configuration option is added.

Serialization retains the segment metadata under the ordinary artifact compatibility contract. This does not add a downstream version-number scheme or a protected-memory API.

Validation

Built the extracted branch with Rust 1.97.1. All 16 tests from tests/all/table.rs passed, including the three new regressions, and the updated call-hook instantiation test passed. These exact test functions were compiled in a small external harness against this branch with Cranelift, async, the copying collector, pooling and call hooks enabled, avoiding unrelated CLI/WASI dependencies. Changed-file formatting and diff checks passed.

Regression cases cover overlapping segments and table copies, explicit null writes, source lifetime after failed startup, partial initialization before a bounds trap, serialized reload, equal initialization fuel, bounded-history fallback, pooled table reuse, and the absence of new host-hook transitions.

Savings depend on the number of function references that remain unused; this moves materialization to access rather than removing its cost for functions actually used.

Active element segments targeting imported tables eagerly materialize native function-reference records, even when those entries are never used. This extends Wasmtime's existing lazy function-table initialization to eligible imported-table segments.

Store immutable function indices in shared module metadata and source-instance/range bindings on the table. The existing lazy-read path materializes a reference from its contributing instance on first access. Later segments override earlier ranges, and explicit table writes, including nulls, override deferred entries.

Per-table bindings are capped at 128 to bound metadata and first-access lookup costs. Unsupported segments, a full binding list or metadata allocation failure use eager initialization. Bounds checks, segment ordering and fuel charges remain at their existing initialization boundaries. The Store retains source instances after failed startup, and pooled table reuse clears deferred bindings.

The new fallible initializer suppresses host-call hooks to preserve the previous ref_func behavior; other calls keep their existing hooks.

Memory benefit

A local population comparison in the downstream convex-wasm-compiler integration, with approximately 47,000 side-module function references, saved 0.962 MiB of host resident memory per application instance:

MiB per instance Eager Deferred
Marginal host anonymous resident memory 2.862 1.900
Guest anonymous memory 7.109 7.109

Both variants used identical Core Wasm, inputs and collection policy. Host memory was estimated from the increase when adding four instances to four already warmed instances. This is a population estimate, including allocator effects. Allocated capacity was essentially unchanged; the saving comes from leaving unused function-reference pages untouched. Savings depend on how many references the workload uses.

Validation

All 16 tests in tests/all/table.rs and the call-hook instantiation regression passed in a focused harness against this branch with copying GC and pooling enabled. Coverage includes overlapping segments and table copies, explicit null writes, source lifetime after failed startup, partial initialization before a bounds trap, serialized reload, unchanged fuel charges, bounded-history fallback and pooled table reuse.
