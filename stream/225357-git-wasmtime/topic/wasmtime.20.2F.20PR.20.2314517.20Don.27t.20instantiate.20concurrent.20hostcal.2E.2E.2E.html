HostFn::run returned a HostResult enum with a Future variant, so the sync and async lowering paths always contained the poll_and_block and first_poll arms. Those are monomorphized per host closure, so every func_wrap, func_wrap_async, func_new and func_new_async host function compiled its own copy of the future path, even though only the concurrent constructors can return a future.

This replaces the enum with a small HostOutput trait implemented for Result and for the boxed future. Only the future impl calls poll_and_block and first_poll, so they're only compiled for concurrent host functions. No public API or behavior change.

For the wasmtime CLI this cuts the wasmtime-cli crate's LLVM IR by 26% (7.4M to 5.5M lines), its peak compile memory from 3.3 GB to 2.5 GB, and the release binary from 65.8 MB to 60.8 MB. On an embedder with around 2,000 bindgen imports the fat LTO link peak went from 18.6 GB to 16.4 GB.

This overlaps a little with #13876. Its poll_once fast path would move into the future impl.

  • cargo test --test all, component-async-tests, wasmtime-wasi and wasmtime-wasi-http (p3) pass.
  • cargo check -p wasmtime without component-model-async.
  • benches/call.rs component wasm-to-host benches are unchanged within noise.
