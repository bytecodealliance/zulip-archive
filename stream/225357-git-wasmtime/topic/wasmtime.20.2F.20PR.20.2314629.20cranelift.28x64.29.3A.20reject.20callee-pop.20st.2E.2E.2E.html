rvolosatovs opened PR #14629 from rvolosatovs:fix/x64-large-callee-pop to bytecodealliance:main:

The tail and winch calling conventions pop their stack arguments on return, which x64 does with ret imm16. gen_return converted the size with u16::try_from(..).unwrap(), but stack arguments may be up to 128 MiB, so compiling a tail or winch function with 64 KiB or more of stack arguments, or a tail function that return_calls such a callee, panicked.

Reject such signatures with CodegenError::ImplLimitExceeded in compute_arg_locs, alongside the existing stack-argument size limit. Since this runs for every signature a function references, it also covers the callee's signature at return_call sites, which grows the caller's tail-argument area. Other backends pop with an sp adjustment and aren't affected. Wasm can't reach this: 1000 parameters is about 16 KiB of stack arguments.
