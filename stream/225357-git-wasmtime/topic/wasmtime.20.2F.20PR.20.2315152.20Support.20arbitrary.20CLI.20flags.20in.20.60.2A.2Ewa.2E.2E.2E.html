This commit adds support for a feature that I've long wanted the ability to specify, which is arbitrary CLI flags in *.wasts. Such tests aren't the most applicable to other runtimes but they're still quite applicable to our own runtime and testing. While ideally tests don't specify these they're quite useful for one-off scenarios and such. With this commit all of our *.wast tests can now additionally specify flags = "..." like disas tests can which will always be enabled when running the test (or fuzzing with it).

This feature is coupled in this commit with refactoring to make it more natural to implement. The main change is to centralize around the CommonOptions type in the wasmtime_cli_flags as opposed to trying to maintain a separate set of feature getters/setters/etc. This means that all test configuration options are wholly representable in a CommonOptions, and additionally required adding minor features there (such as -Wlegacy-exceptions).

Note though that test configuration is not entirely folded into flags. Like before all tests assume virtually no wasm features are enabled and start from a blank slate. Individual wasm features are still enabled one-by-one in a structured manner, and this enables should_fail calculations to understand the set of wasm features needed for a test. This means we can continue to support lots of *.wast files that are automatically expected to fail on unsupported compilers, but are still run on those compilers, all by just managing a few top-level directives.

Additionally some refactoring is added here to be able to validate that flags doesn't actually specify anything that should otherwise be structurally specified. For example flags cannot contain -Ccompiler because this is an important factor in should_fail, and that predicate needs to be able to run without the wasmtime crate (aka without CLI parsing). The purpose of flags is to contain one-off settings in tests to specifically test one configuration option or such.

Finally fuzzing is additionally updated here. When fuzzing flags specified in tests take precedent over whatever the fuzz configuration says, but otherwise fuzzing will still frob every other possible configuration flag.

The end result of this refactoring is intended to be such that more tests can be migrated from tests/all/*.rs unit tests to *.wast tests without needing harness work for wasts themselves. Instead flags = "..." can be specified and pretty much be done with it.
