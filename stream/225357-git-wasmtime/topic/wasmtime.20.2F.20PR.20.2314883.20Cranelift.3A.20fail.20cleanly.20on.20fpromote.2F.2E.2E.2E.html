ilyas-mallah opened PR #14883 from ilyas-mallah:cranelift-fpromote-fdemote-types to bytecodealliance:main:

The verifier accepts fpromote and fdemote with an f16 or f128 operand. The x64 and aarch64 lowerings match only the result type, and s390x matches any pair. On aarch64 that compiles to a wrong value: fpromote.f64 of an f16 1.0 gives about 2.15e-41, and fdemote.f32 of an f128 gives 0.0. x64 and s390x panic. Wasm doesn't produce these types, so only CLIF reaches this.

The rules now match the source type too, so these pairs fail with the usual unsupported-feature error, as in #14653. riscv64 and Pulley already did. I compiled all 12 type pairs for 8 targets before and after. Only the broken cases changed, and the 24 supported compiles are byte for byte the same.
