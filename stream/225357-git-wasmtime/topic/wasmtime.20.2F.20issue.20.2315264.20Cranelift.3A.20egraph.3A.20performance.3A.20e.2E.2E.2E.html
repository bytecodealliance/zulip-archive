.clif Test Case

A function that adds up the results of N calls, and returns early through a cold block where a call reports an error.
Here N = 3:

function %sum(f64) -> f64 {
    sig0 = (f64) -> f64, i8
    fn0 = %g sig0

block0(v0: f64):
    v1 = f64const 0.0
    jump block1

block1:
    v3, v4 = call fn0(v0)
    v5 = fadd v1, v3
    brif v4, block5, block2

block2:
    v6, v7 = call fn0(v0)
    v8 = fadd v5, v6
    brif v7, block5, block3

block3:
    v9, v10 = call fn0(v0)
    v11 = fadd v8, v9
    brif v10, block5, block4

block4:
    return v11

block5 cold:
    return v1
}

This script writes the same function at any N:

#!/bin/sh
# Writes a function that adds up the results of N calls, returning early where a call reports an error.
n=${1:-4}
printf 'function %%sum(f64) -> f64 {\n    sig0 = (f64) -> f64, i8\n    fn0 = %%g sig0\n\nblock0(v0: f64):\n    v1 = f64const 0.0\n    jump block1\n'
i=1
while [ $i -le $n ]; do
  v=$((3 * i))
  printf '\nblock%d:\n    v%d, v%d = call fn0(v0)\n    v%d = fadd v%d, v%d\n    brif v%d, block%d, block%d\n' \
    $i $v $((v + 1)) $((v + 2)) $([ $i = 1 ] && echo 1 || echo $((v - 1))) $v $((v + 1)) $((n + 2)) $((i + 1))
  i=$((i + 1))
done
printf '\nblock%d:\n    return v%d\n\nblock%d cold:\n    return v1\n}\n' $((n + 1)) $((3 * n + 2)) $((n + 2))

Actual Results

Compile time grows at least quadratically with N: at N = 8,192 register allocation takes 24.5 s and 4.4 GB, and with
the patch 0.051 s and 68 MB. The instructions retired by clif-util grow 4.7, 5.7 and 6.5 times per doubling of N,
and peak memory 3.6 to 3.9 times:

"Register allocation" is the -T line for Cranelift's call into regalloc2, so its time is regalloc2's. The
instructions retired include parsing, verification and every other pass. Each figure is from one run, on a machine
whose load average was about 10 at the time.

Extra Info

Elaboration places a pure instruction just before its first use in the skeleton. Each fadd of the sum is used only
by the next fadd, and the last only by the return, so every fadd is placed in the last block. Each call's
result is then live from its call to the end of the function, across every later call and block. With N calls that
is N live ranges, each spanning up to N blocks, and the work of regalloc2 grows with their product.

The patch moves a pure instruction that is the last use of one of its operands to just after its latest operand.
That ends the operand's range and starts its own, so the sum interleaves with the calls. It applies these limits:

  • it moves an instruction only past a skeleton instruction;

  • it never makes an instruction run anywhere new, so a move into another block needs the instruction's block to
    post-dominate that block among warm blocks, and to be in every loop that contains it;

  • it leaves in place an instruction whose result a skeleton instruction uses, so that lowering can still merge the
    two, as an icmp into a brif;

  • it copies a constant once per block where the constant no longer dominates its user.

Because of the second limit, the early exits must be cold. With cold removed from the test case, the last block no
longer post-dominates the others, and at N = 2,048 the patched and stock clif-util both retired 7.3G instructions.
