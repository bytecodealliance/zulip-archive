alexcrichton opened PR #14906 from alexcrichton:remove-thread-switching to bytecodealliance:main:

This commit adjusts the behavior added in #12736 where the thread identity was saved/restored around component model futures/streams being completed. Later in #13949 though the spec was refined to clarify that thread identity during lowering is not possible to witness, which meant that after that change the thread-switching was technically all dead code. Thread IDs can go away at any time and aren't required to outlive future/stream operations, so this now-vestigial code can lead to spurious traps using wrong table slots. Here all the switching is just removed entirely since it's no longer necessary.
