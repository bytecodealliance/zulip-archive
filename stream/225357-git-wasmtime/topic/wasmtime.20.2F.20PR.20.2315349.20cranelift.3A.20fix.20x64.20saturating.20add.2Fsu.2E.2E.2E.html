Fixes #15279.

On x64, sadd_sat/ssub_sat of 32- and 64-bit lanes have no single
instruction, so they are lowered as a wrapping add/sub followed by overflow
detection. The detection reuses both operands, but the second operand of the
wrapping operation is an XmmMem128:

function %f(i32x4, i64) -> i32x4 {
block0(v0: i32x4, v1: i64):
    v2 = load.i32x4 v1
    v3 = sadd_sat v0, v2
    return v3
}
The load is sunk into the wrapping vpaddd as a memory operand, and the
overflow detection then asks for the same value in a register, which trips the
inst_sunk assertion in put_value_in_regs.
Materialize both operands in registers before the wrapping operation. The
loaded operand becomes a vmovdqu that is reused by the detection instead of
being folded into the arithmetic. This fixes all four affected forms
(sadd_sat/ssub_sat for i32x4/i64x2).
I kept the fix in the lowering rules rather than in the sink logic: the CLIF
value still has a single use and only the rule knows it is consumed twice, so
this is the conservative place to make the register requirement explicit.
Tests:
- New cranelift/filetests/filetests/isa/x64/sat-arith-load.clif covering
sadd_sat/ssub_sat for i32x4/i64x2 with a loaded operand, plus a
two-load case.
- cargo test -p cranelift-tools --test logged-filetests
- cargo test -p cranelift-codegen

to help draft this patch and its tests. I reviewed every change, ran the
relevant tests locally, and can explain the reasoning behind the
implementation.
