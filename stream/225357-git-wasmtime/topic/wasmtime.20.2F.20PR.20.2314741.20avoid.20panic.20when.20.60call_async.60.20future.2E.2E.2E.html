As the test illustrates, it's possible for such a future to be dropped when it has been queued to run (i.e. is no longer in the instance's pending set due to backpressure) but has not yet been run. Prior to this patch, that led to a panic in TypedFunc::call_async_concurrent::SignalDrop::drop. This addresses that by modifying StoreOpaque::cancel_guest_subtask_without_lowered_parameters to look for and remove any matching tasks in the
ConcurrentState::high_priority and ConcurrentState::low_priority queues if they weren't found in the pending set.
