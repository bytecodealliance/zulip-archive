Closes #11125.

On x64, brif, select, trapz/trapnz and icmp eq/ne against zero on the result of an iadd, isub, bor or bxor now use that instruction’s flags instead of a separate test:

orl   %esi, %edi          orl   %esi, %edi
testl %edi, %edi    =>    jnz   ...
jnz   ...

The op uses its exact width, so for i8/i16 ZF only sees the low bits. Only zero/nonzero conditions are folded, since OF/CF differ from test. The result is an opportunistic def (#14228), so a value that is used again later is still computed once.

The rules only fire when the op is in the same block and its other uses are already lowered. Otherwise the op gets emitted twice, which made crit-edge.clif worse. For that check, compute_use_states now also returns exact use counts. I’m happy to drop the check if you’d rather not touch lower.rs.

On 25 Sightglass modules, code size goes down 0.14%. I also tried cmp for single-use isub/bxor, as the issue suggests, but it wasn’t smaller. There are new precise-output and run tests, and all filetests pass.

Thanks for this change, @JonSnow1807 ! Can you detail why you had to modify the lowering logic to have a separate "foldable" predicate? I am pretty concerned about the complexity and duplication/partial overlap with our other lowering logic: I don't want yet another definition of a "foldable" op with its own subtle conditions.

I had at least naively hoped that the opportunistic-def mechanism would be enough here. Basically we want to match on is_nonzero-of-op and emit the op itself as an opportunistic def as you've done; what happens if we elide the "foldable" predicate there? We emit the ALU op instead of the test? I guess that slightly increases register pressure (extending liverange of the two inputs rather than using the one output) but I'd want to see Sightglass data on this simpler alternative before discarding it.

The complexity around 8- and 16-bit exact values is also IMHO not worth it -- testing nonzero on those ops is such a niche thing that I don't want to introduce the complexity risk of having special lowerings here.

Wasmtime GitHub notifications bot (Nov 10 2026 at 17:39):

JonSnow1807 commented on PR #15220:

Thanks for taking this! The predicate was there to avoid computing the op twice: if the op is defined in another block, or its value is used before the branch, the opportunistic def isn't taken, so the op is emitted at its definition and again at the branch. In crit-edge.clif that showed up as a mov + add instead of a test. But it doesn't buy much: on the same 25 Sightglass modules, the version without it reduces code size by 0.126% vs 0.139% with it, and the instruction counts are almost the same. So I'm happy to drop it, along with the 8/16-bit handling. I'll push that and post Sightglass runtime numbers for main vs the simpler version.
