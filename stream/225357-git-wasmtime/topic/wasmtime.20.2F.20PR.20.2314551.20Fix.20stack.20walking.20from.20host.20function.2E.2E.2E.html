We weren't zeroing out the old VMStoreContext::last_wasm_* values when creating an EntryStoreContext, and then stack walking from a host function that was Func::called from another host function would see those last_wasm_* values both in the VMStoreContext and in the activation chain, which would lead to duplicate stack frames in the backtrace and tracing on-stack GC roots twice.

Fixes #14463
