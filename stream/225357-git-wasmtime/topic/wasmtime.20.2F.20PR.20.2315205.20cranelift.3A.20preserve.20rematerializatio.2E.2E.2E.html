wraitii opened PR #15205 from wraitii:fix/egraph-cloned-remat to bytecodealliance:main:

Egraph elaboration can clone instructions when placing them in separate dominance scopes, including when LICM hoists constants. These clones receive new value IDs that the rematerialization set does not recognize, potentially extending live ranges and increasing register pressure.

Check rematerialization eligibility through the existing value_to_best_value mapping so clones retain the original value’s eligibility.

Add regression coverage for a cloned constant hoisted out of a loop and a cloned non-constant instruction without loops. Both cases fail before the fix.

Validation: 82 egraph test files and 216 codegen unit tests pass.

PR written by GPT 6.1 sol following investigation by Opus 5.5 . Leads to obvious incorrect spilling of constants in a JS JIT I'm working on. As with my earlier PRs, I've spot-checked that the diff looks correct for what the AIs report the problem is, but I cannot really confirm that this is the minimal or cleanest fix, feel free to pong back.
