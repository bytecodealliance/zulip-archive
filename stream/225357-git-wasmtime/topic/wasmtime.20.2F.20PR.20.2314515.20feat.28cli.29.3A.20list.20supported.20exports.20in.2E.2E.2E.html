Aditya-9-6 opened PR #14515 from Aditya-9-6:component-supported-exports-error to bytecodealliance:main:

Summary

Improves the error message when failing to execute a WebAssembly component that does not export the expected command or proxy interface handlers.

Closes #14099.

Details

  1. \wasmtime run\:

    • Updates the outer context in \instantiate_and_run\ to refer to \ ailed to run component <target>\ when executing a component (\RunTarget::Component\), while preserving \ ailed to run main module <target>\ for core modules (\RunTarget::Core\).
    • When attempting to instantiate CLI command bindings in \
      un_command_component\, if neither WASIp3 nor WASIp2 bindings match due to missing exports, Wasmtime reports:
      \\\ ext
      The component doesn't export any of the supported handlers. The component must export at least one of:
      an instance of the interface \wasi:cli/run@0.2\`n an instance of the interface \wasi:cli/run@0.3\`n \\\`n (If Preview 3 is disabled via \--wasi p3=n\, only \@0.2\ is listed).

  2. \wasmtime serve\:

    • Updates the outer context in \ServeCommand::execute\ to format \ ailed to serve component <target>\.
    • In \serve_maybe_debug\, if neither WASIp3 \ServicePre\ nor WASIp2 \ProxyPre\ can be instantiated, Wasmtime reports:
      \\\ ext
      The component doesn't export any of the supported handlers. The component must export at least one of:
      an instance of the interface \wasi:http/incoming-handler@0.2\`n an instance of the interface \wasi:http/incoming-handler@0.3\`n \\\`n (If Preview 3 is disabled via \--wasi p3=n\, only \@0.2\ is listed).

  3. Tests:

    • Added \component_missing_run_exports_error\ and \component_missing_serve_exports_error\ in \ ests/all/cli_tests.rs\ asserting the formatted error outputs under default and \--wasi p3=n\ configurations.
