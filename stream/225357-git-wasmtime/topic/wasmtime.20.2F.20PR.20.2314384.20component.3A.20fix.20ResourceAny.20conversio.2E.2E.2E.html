Closes #7793.

Motivation

Converting a Resource::<T>::new_borrow(rep) (or ResourceDynamic::new_borrow) into a ResourceAny eagerly inserted a borrow into the host resource table. That operation requires an active component call scope, so performing the conversion outside of a call reached bail_bug!("no current scope"), which panics in debug builds and returns a WasmtimeBug error in release builds. @rvolosatovs reported this in #7793 with a minimal reproducer, and @alexcrichton pointed out that borrow lowering has to be deferred until a call is actually in progress, the way Resource<T> already does it. The reproducer has been sitting commented out in can_use_own_for_borrow since then.

Changes

  • ResourceAny now carries an internal ResourceAnyIndex that is either a host table index (unchanged behavior for every existing ResourceAny) or the raw rep of a synthetic borrow.
  • HostResource::try_into_resource_any returns the synthetic variant for new_borrow resources instead of touching the host table. Owned and table-backed resources are handled exactly as before.
  • try_into_resource / try_into_resource_dynamic, resource_drop, and the own/borrow lowering paths handle the new variant; lift is unchanged and still produces table-backed values.
  • Update the ResourceAny docs to state which values require resource_drop, and add a release note.
  • Tests: enable the previously disabled part of can_use_own_for_borrow and extend it with the typed round-trip, a type mismatch, the own-lowering error, and the forgotten-drop trap; resource_dynamic gains the same paths for ResourceDynamic.

Design

The synthetic variant has no host table slot, so conversion, the typed round-trip, and resource_drop no longer need a call scope; resource_drop on such a value is a documented no-op. When the value is lowered into a guest borrow parameter, lower_to_index passes the rep straight to guest_resource_lower_borrow, which runs during the call and keeps guest-side borrow accounting intact: a guest that fails to drop the handle still traps with "borrow handles still remain at the end of the call". Lowering a synthetic borrow as own keeps producing the existing "cannot lower a borrow resource into an own" error, and resource type checks run before either lowering path. Borrows lifted from a guest remain table-backed and keep their drop obligation, so nothing changes for embedders who never call new_borrow.

One behavior change worth calling out for review: previously, converting a new_borrow resource while a call was already active would create a table-backed borrow that had to be dropped before that call returned. That obligation no longer exists, which matches how Resource<T> borrows behave when passed directly. Happy to adjust if a different policy is preferred.

Testing

cargo test --test all component_model::resources

Locally: fmt, clippy, and the full component_model test suite pass. The baseline reproduces the BUG: no current scope panic on main.

Thanks to @rvolosatovs for the clear reproducer and root-cause analysis, and to @alexcrichton for pointing at the deferred-lowering approach.
