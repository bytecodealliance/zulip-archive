The gdbstub component acknowledged a client's interrupt request (Ctrl-C) without asking the debuggee to stop, so interrupting a running program had no effect until its next debug event. Call debuggee.interrupt() and report the resulting interrupted event as the stop.

This PR also adds a protocol-level test, using a minimal GDB remote protocol client, that interrupts a long-running loop. (This little test stub is also useful for later PRs I plan to send.)
