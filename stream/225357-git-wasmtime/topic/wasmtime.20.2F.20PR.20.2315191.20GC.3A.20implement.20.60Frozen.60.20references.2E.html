cfallin opened PR #15191 from cfallin:gc-frozen-refs to bytecodealliance:main:

In order to implement record/replay, we need a little more discipline around read-only vs. read-write Stores. It turns out that rooting mutates a store. This is unfortunate when we want to permit debuggers to inspect the state of a store, including its GC heap, on a read-only trace replay.

Separately, the need for a mutable store borrow to access any GC object, even on actions that are nominally/semantically read-only, makes APIs more awkward and looser about mutation than they could otherwise be. One can see artifacts of this awkwardness in e.g. the existence of a separate getter for globals that only reads non-GC values, with an immutable store.

Separately separately, rooting is expensive if all one wants to do is introspect the Store's GC heap while execution is completely frozen. Ideally one would use raw heap offsets ("pointers") and just read out the objects without setting up and tearing down rooting metadata.

All of these problems are solved in this PR with the addition of a new Frozen GC ref kind. The idea is that we:

  • Give the GC heap a u64 counter that increments on any possible mutation (i.e.: every entry or return into Wasm, and every host-API mutation to GC objects);

  • Hand out frozen refs that wrap up the raw u32 offset into the GC heap with a snapshot of that counter (the "GC epoch counter");

  • Make uses of the refs fallible: one can deref them only when the epoch counter matches, but they become "stale" and fail after that.

These frozen refs are sufficient to read the whole GC heap when the store is frozen (e.g., during a debug event or at any step during a trace replay).

What's more, this actually heads to a nice generalization: we can make the rooting step explicitly opt-in everywhere by changing all GC getter APIs to return frozen refs by default. One can then take that frozen ref and turn it into a Rooted<T> or OwnedRooted<T> if one wants to actually root it during further execution, and only needs a mutable store borrow at that point to create the root. This makes the cheap option (copy a u32 and u64) the default and makes the rooting cost pay-as-you-go.

I continue to personally be wary of tracking a GC epoch

Yep, I think this is unfortunately just kind of fundamental. The thing that we need is tracking of a dynamic lifetime: a pointer that is valid until something invalidates it. That is required because GC roots mutate the store, and we need to access (but not modify) the GC heap when we don't have mutable access to it. So the only ways out are:

  • GC roots not mutate the store (but this contradicts what a root does: it can keep objects alive for longer)
  • Avoid the need to access the GC heap when frozen (but this then means that we cannot debug a trace replay)
  • Track the dynamic invalidation some other way, e.g. with an explicit dependency-tracking mechanism

So basically, the way out is to either not implement record/replay, or not implement debugging on record/replay. In other words, I think if we agree we want those features, we are stuck.

The remaining safety path is to encapsulate as much as possible. Maybe we could build some generic mechanism (in the same spirit as Accessor for the async stuff) that holds a T and gives out either frozen refs or mutable refs and tracks the epoch alongside, in a way that can't be violated. Something like:

struct EpochTrackedState<T> {
  inner: T,
  stamp: StateId,  // like a store ID; globally allocated
  epoch: EpochCounter,
}

impl<T> EpochTrackedState<T> {
  // ...

  fn frozen_ref(&self) -> TrackedStateFrozenRef<T> {
    TrackedStateFrozenRef { stamp: self.stamp, epoch: self.epoch } // no borrow of `self`
  }
  fn get_mut(&mut self) -> &mut T {
    self.epoch.increment();
    &mut self.inner
  }

  fn get(&self, ref: TrackedStateFrozenRef<T>) -> Option<&T> {
    assert_eq!(self.stamp, ref.stamp);
    if self.epoch != stamp.epoch { None } else { Some(&self.inner) }
  }
}

then put the whole GC state inside of that. What do you think?

In order to implement record/replay, we need a little more discipline around read-only vs. read-write Stores. It turns out that rooting mutates a store. This is unfortunate when we want to permit debuggers to inspect the state of a store, including its GC heap, on a read-only trace replay.

Separately, the need for a mutable store borrow to access any GC object, even on actions that are nominally/semantically read-only, makes APIs more awkward and looser about mutation than they could otherwise be. One can see artifacts of this awkwardness in e.g. the existence of a separate getter for globals that only reads non-GC values, with an immutable store.

Separately separately, rooting is expensive if all one wants to do is introspect the Store's GC heap while execution is completely frozen. Ideally one would use raw heap offsets ("pointers") and just read out the objects without setting up and tearing down rooting metadata.

All of these problems are solved in this PR with the addition of a new Unrooted GC ref kind. The idea is that we:

  • Give the GC heap a u64 counter that increments on any possible mutation (i.e.: every entry or return into Wasm, and every host-API mutation to GC objects);

  • Hand out frozen refs that wrap up the raw u32 offset into the GC heap with a snapshot of that counter (the "GC epoch counter");

  • Make uses of the refs fallible: one can deref them only when the epoch counter matches, but they become "stale" and fail after that.

These unrooted refs are sufficient to read the whole GC heap when the store is frozen (e.g., during a debug event or at any step during a trace replay).

What's more, this actually heads to a nice generalization: we can make the rooting step explicitly opt-in everywhere by changing all GC getter APIs to return unrooted refs by default. One can then take that unrooted ref and turn it into a Rooted<T> or OwnedRooted<T> if one wants to actually root it during further execution, and only needs a mutable store borrow at that point to create the root. This makes the cheap option (copy a u32 and u64) the default and makes the rooting cost pay-as-you-go.
