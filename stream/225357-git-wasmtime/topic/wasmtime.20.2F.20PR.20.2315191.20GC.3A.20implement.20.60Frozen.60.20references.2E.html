In order to implement record/replay, we need a little more discipline around read-only vs. read-write Stores. It turns out that rooting mutates a store. This is unfortunate when we want to permit debuggers to inspect the state of a store, including its GC heap, on a read-only trace replay.

Separately, the need for a mutable store borrow to access any GC object, even on actions that are nominally/semantically read-only, makes APIs more awkward and looser about mutation than they could otherwise be. One can see artifacts of this awkwardness in e.g. the existence of a separate getter for globals that only reads non-GC values, with an immutable store.

Separately separately, rooting is expensive if all one wants to do is introspect the Store's GC heap while execution is completely frozen. Ideally one would use raw heap offsets ("pointers") and just read out the objects without setting up and tearing down rooting metadata.

All of these problems are solved in this PR with the addition of a new Frozen GC ref kind. The idea is that we:

  • Give the GC heap a u64 counter that increments on any possible mutation (i.e.: every entry or return into Wasm, and every host-API mutation to GC objects);

  • Hand out frozen refs that wrap up the raw u32 offset into the GC heap with a snapshot of that counter (the "GC epoch counter");

  • Make uses of the refs fallible: one can deref them only when the epoch counter matches, but they become "stale" and fail after that.

These frozen refs are sufficient to read the whole GC heap when the store is frozen (e.g., during a debug event or at any step during a trace replay).

What's more, this actually heads to a nice generalization: we can make the rooting step explicitly opt-in everywhere by changing all GC getter APIs to return frozen refs by default. One can then take that frozen ref and turn it into a Rooted<T> or OwnedRooted<T> if one wants to actually root it during further execution, and only needs a mutable store borrow at that point to create the root. This makes the cheap option (copy a u32 and u64) the default and makes the rooting cost pay-as-you-go.
