jrandolf opened PR #14869 from jrandolf:c-api-null-name to bytecodealliance:main:

Several functions in the component C API passed a name pointer and length straight to std::slice::from_raw_parts. That's UB for a null pointer even when the length is zero, which is exactly what the C++ API passes for a default std::string_view, and debug builds abort with "unsafe precondition(s) violated". There were 10 of these: the component and instance type lookups, the five linker add_* functions, and the two get_export_index functions. They now use the existing slice_from_raw_parts helper, like the rest of the C API.

The new tests only crash without the fix in a debug build, which is what CI uses.
