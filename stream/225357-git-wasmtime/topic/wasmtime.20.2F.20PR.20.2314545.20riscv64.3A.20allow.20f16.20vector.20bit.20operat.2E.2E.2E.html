Fixes #12195.

Several RISC-V lowering rules require Zvfh for f16 vectors even when they only use the bit representation. With only the base V extension, this causes compilation failures, including panics when lowering f16x8 bitcasts and loads/stores.

The f16x8 to i128 bitcast in #12195 is one such case.

Since Cranelift has no dedicated type for raw bits, this checks support using an integer vector type with the same lane width and lane count, while preserving the original type. This applies to loads/stores, constants, bitcasts, select, and bitwise AND/OR/XOR/NOT, which can use base V instructions without requiring FP16 arithmetic support.

Adds precise-output filetests for these paths and runs the existing f16 vector constant test with has_zvfh disabled. The RISC-V filetests pass. Copy and bitcast results were also checked under QEMU 9.2.0 with and without Zvfh. The original function from #12195 also returns the expected result under QEMU with Zvfh disabled.
