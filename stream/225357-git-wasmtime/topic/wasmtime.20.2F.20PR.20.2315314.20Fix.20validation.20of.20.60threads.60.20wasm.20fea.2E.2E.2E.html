When the threads Cargo feature is disabled it was intended that the wasm threads feature was not supposed to be enabled. With the semi-recent introduction of Config::wasm_features, however, it was possible to turn this on without Wasmtime knowing. If the wasm threads feature is enabled in a threads-cargo-feature-disabled build then memory.atomic.* instructions use libcalls that are unreachable!() stubs and as a result abort the process.
