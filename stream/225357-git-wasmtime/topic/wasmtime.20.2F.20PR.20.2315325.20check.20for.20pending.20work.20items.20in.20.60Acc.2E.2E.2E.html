This addresses a condition in wasmtime_wasi_http::handler where a worker may accept new requests faster than it can deliver events to existing tasks, leading to starvation and potential resource exhaustion.

The solution is to check for any ready-to-run work items in Accessor::poll_ready_for_concurrent_call and, if any are found, return Poll::Pending, which directs wasmtime_wasi_http::handler::Worker::run_ to return control to the event loop so it can drain the items before taking on new work.
