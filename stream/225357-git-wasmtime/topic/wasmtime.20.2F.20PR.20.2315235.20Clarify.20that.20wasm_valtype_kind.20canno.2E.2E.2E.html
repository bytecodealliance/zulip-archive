wasm_valtype_kind aborts for v128 and for reference types that
wasm_valkind_t cannot express. The documentation in doc-wasm.h mentioned
the abort but never said what to use instead, which is what #15088 ran into.

This documents wasmtime_valtype_t / wasmtime_valtype_new as the supported
path for those types in both doc-wasm.h and wasmtime/types/val.h. It also
fixes the abort messages, which previously said that support for v128
was not implemented. v128 is implemented; it just cannot be represented
by wasm_valkind_t.

I verified this by building the C API and running the reproducer from the
issue; it now prints guidance on which API to use before aborting.

Closes #15088
