We previously set needs_gc_heap = true when creating a GcCompiler, but unfortunately this was not a complete bottleneck for GC heap access because collector-agnostic accesses (e.g. ref.tests that only read the GC header word) do not construct a GcCompiler before emitting code to access the GC heap. This meant that needs_gc_heap was not set, and therefore we didn't pre-allocate a GC heap upon the module's instantiation, which meant that compiled Wasm code could read the initial dangling GC heap base pointer, read the null page, and trigger a process abort.

This commit fixes the bug by setting needs_gc_heap = true when creating the GC heap's Heap and when emitting code to access its base and bound. It additionally adds a few tactical assertions that we have marked needs_gc_heap = true, such as when getting the GC memflags.
