alexcrichton opened PR #14507 from alexcrichton:refactor-release-memory to bytecodealliance:main:

This commit first refactors the logic added in #14419 to avoid open-coding the index allocator internals in more than one location. A new AllocMode is used to encapsulate "only warm" and then the internal implementation of "take all warm slots" is a simpler loop than before.

This then additionally fixes a bug in the implementation where the decommit_pages call was done only for the first bytes_resident pages, but with features like PAGEMAP_SCAN enabled these bytes could be sparsely contained within the slot, so now the madvise happens for the entire slot rather than just the number of resident bytes.

Finally, this documents a consequence of the current implementation which is that concurrent instantiations may fail while the method is running. The fix doesn't seem worth it at this time so I figured it was at least good to document.
