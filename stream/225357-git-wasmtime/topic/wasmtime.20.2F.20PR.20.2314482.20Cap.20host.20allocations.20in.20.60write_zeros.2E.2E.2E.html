alexcrichton opened PR #14482 from alexcrichton:cap-write-zeros to bytecodealliance:main:

This commit builds on the mitigation applied for GHSA-852m-cvvp-9p4w in #12652. In that PR write_zeros was limited, but only to the return value of check_write. Notably the SinkOutpuStream helper within wasmtime-wasi would yield usize::MAX for the check_write value and effectively ignore the mitigation. The fix here is to reduce the magnitude of values returned by check_write. This additionally audits all preexisting check_write calls and fixes a case in wasi:tls where the return value was 1GB as well. All values are now capped at the previously capped read buffer value of 64k.

part of https://github.com/bytecodealliance/wasmtime/security/advisories/GHSA-gqmc-89g8-p25r
