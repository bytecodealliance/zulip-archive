cfallin opened PR #15222 from cfallin:fix-frame-handle to bytecodealliance:main:

We keep an "execution version" in the store that is used to invalidate FrameHandles, which are a part of the debug API that can introspect guest-execution stack frames. These frame handles must not themselves hold borrows of the store (because debuggers are allowed to mutate execution), but must be usable with the store only and exactly when they still point to valid frames. Invalidation on any Wasm execution is how we enforce this.

Unfortunately while we added an epoch-bump to ordinary Wasm-to-host trampolines, we missed it in Wasm-to-builtin trampolines; and this kind of host entry can also lead to arbitrary actions/additional execution in the Wasm that could invalidate frame handles. (Most simply: two breakpoints at different points in Wasm execution, with no other hostcalls in-between: the first could capture a frame handle and the second could try to use it, even if Wasm execution unwound frames arbitrarily in the meantime.) Basically, we need to bump the epoch whenever returning to Wasm execution, including from builtins. This PR makes that fix.
