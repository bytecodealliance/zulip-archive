alexcrichton opened PR #14730 from alexcrichton:fix-same-instance-adapter to bytecodealliance:main:

This commit fixes an accidental regression from #14146 where if a same-instance lift/lower transferring a string provided overlapping ranges for a string transcode it could cause a panic on the host. The changes in #14146 are downstream of various spec changes which have adjusted rules in this precise scenario over time, and technically the spec allows these sorts of calls in its current iteration. All of component-to-component adaptation in Wasmtime, however, assumes that the precise order of operations is not semantically visible which is violated should same-instance adaptations be allowed. The fix here is to restore a trap in same-instance adaptations, and the next steps here will be to have a follow-up with the spec to figure out a long-term solution.
