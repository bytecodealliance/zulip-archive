Fixes #3295

Why

The x64 backend had no lowering for sadd_sat on i32x4 or i64x2. Since x86 has no packed signed saturating-add instruction for those lane widths and there was no legalization fallback, these operations failed with an ISLE lowering error.

What changed

  • Add SSE2-based lowerings for i32x4 and i64x2 signed saturating addition.
  • Detect signed overflow per lane and select the appropriate MIN or MAX saturation value.
  • Update x64 fuzzgen so it no longer excludes sadd_sat for these types.
  • Add an x64 regression test covering overflow, boundary values, and non-overflowing lanes on baseline and AVX targets.

Testing

  • cargo +1.97.0 fmt --all -- --check
  • cargo +1.97.0 test -p cranelift-codegen
  • cargo +1.97.0 test -p cranelift-filetests
  • cargo +1.97.0 test -p cranelift-tools --test filetests
  • cargo +1.97.0 test -p cranelift-tools --test logged-filetests
  • cargo +1.97.0 test -p cranelift-fuzzgen
  • cargo +1.97.0 check -p cranelift-fuzzgen
  • Ran the regression test and issue reproducer with clif-util; both passed.
  • Ran an additional generated stress test with 400 random cases for each vector type and all i64x2 boundary pairs; all passed natively.
  • Compile-checked AVX and AVX-512 targets. The AVX runtime variant ran on the host; AVX-512 was compile-checked only.
