jrandolf opened PR #14970 from jrandolf:implements-default to bytecodealliance:main:

WASI 0.3.1 and later require runtimes to support implements and external-id (see #14800), so this enables the feature by default.

The one box it doesn't tick is fuzzing. As discussed on #14914, whether that's needed isn't a decision for one person, so this PR is the place to decide it. My case for not gating on it: the attributes are metadata that don't affect type checking, compilation or execution. Wasmtime copies them into its type information and returns them from ComponentExtern. The code that interprets them (ComponentExtern::is_implements, bindgen!'s named_imports and the named WASI imports) is covered by tests. The stability table keeps the :cross_mark: with a footnote saying so.

<details>
<summary>LLM summary of the changes</summary>

  • Config enables CM_IMPLEMENTS whenever the component-model crate feature is on, like the component model itself, and Config::wasm_component_model_implements documents that default instead of calling the feature a work in progress.
  • docs/stability-wasm-proposals.md moves implements to the on-by-default table with a footnote on its Fuzzed :cross_mark:.
  • implements_enabled_by_default checks that a default Engine accepts an implements import. The .wast harness still turns the feature off unless a test asks for it, so implements-disabled.wast still checks the error.

</details>
