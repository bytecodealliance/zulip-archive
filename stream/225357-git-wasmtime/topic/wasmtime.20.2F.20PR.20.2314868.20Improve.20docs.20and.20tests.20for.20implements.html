jrandolf opened PR #14868 from jrandolf:implements-docs-tests to bytecodealliance:main:

This fixes docs around implements and named imports that had drifted from the implementation, and adds tests for paths that had no coverage.

Docs:

  • ComponentExternData::implements said it's used to match imports by interface name, but imports are only resolved by their own name.
  • The bindgen! named_imports docs said the id is passed by reference and that interfaces with resources aren't supported. Neither is true anymore. They now also explain how labelled imports are bound with and without named_imports.
  • The WASI named views (WasiNamedView, WasiHttpNamedView and the per-interface ones) said their ResourceTable doesn't need to be shared. It has to be the default context's table, because resources flow between named and plain interfaces; for example, a stream from a named wasi:cli/stdout is used through wasi:io/streams.
  • The config and CLI flag docs now mention external-id next to implements, and a few typos are fixed.

Tests:

  • The bindgen! implements test now actually puts (implements ...) on its imports. Before, they were plain imports.
  • An interface exported twice under different labels, called through bindgen!.
  • The Linker resolves a labelled import only by its label, never by the interface it implements (and vice versa), and two labels get separate definitions.
  • Semver edge cases for ComponentExtern::is_implements.
  • Loading a precompiled component that uses implements into an engine with the feature disabled fails, and external-id is rejected when the feature is disabled.

None of the new tests found a bug. I checked that each one fails against a deliberately broken implementation.

Closes #14857
