Currently the threads Cargo feature on the wasmtime crate implies std (threads = ["std"]). This prevents #![no_std] embedders (such as bare-metal or kernel hosts loading precompiled AOT modules with custom-sync-primitives) from enabling WasmFeatures::THREADS, executing WebAssembly atomic instructions, or sharing a SharedMemory across multiple Stores on separate host threads.

This commit decouples threads from std with a minimal set of runtime changes and without expanding the wasmtime-platform.h C API:

  • Remove "std" from the threads feature in crates/wasmtime/Cargo.toml and switch SharedMemory from std types to core/alloc plus crate::sync::RwLock (which delegates to std::sync::RwLock when std is enabled, host locks when custom-sync-primitives is enabled, or panic-on-contention in single-threaded no_std builds).

  • Route SharedMemory::new through Config::with_host_memory (falling back to DefaultMemoryCreator) instead of hardcoding MmapMemory. Module-defined shared memories in Memory::new_dynamic already used MemoryCreator, whereas SharedMemory::new directly called MmapMemory::new, which is unavailable when !cfg!(has_virtual_memory) and ignored custom MemoryCreators. LocalMemory already enforces memory_may_move == false for shared memories so growth never relocates the base pointer beyond the initial allocation capacity.

  • Gate ParkingSpot behind #[cfg(feature = "std")]. In no_std builds, atomic_notify, atomic_wait32, and atomic_wait64 still perform alignment and bounds checks; atomic_notify returns Ok(0) and atomic_wait32/64 handle value mismatches (WaitResult::Mismatch) and zero-duration timeouts (WaitResult::TimedOut), panicking only if a guest attempts a blocking memory.atomic.wait without std.

  • Guard AtomicU64 usage on cfg(target_has_atomic = "64") and bail in SharedMemory::wrap when 64-bit atomics are unavailable so 32-bit no_std targets such as riscv32imac-unknown-none-elf continue to build cleanly with --features threads.

  • Add a shared_memory_uses_custom_creator test, enable threads in the no_std CI checks, and list threads in the #![no_std] platform support documentation.
