wasi-preview1-component-adapter: nonblocking regular-file read returns EAGAIN before host I/O completes

Summary

A regular file opened with O_RDWR|O_NONBLOCK immediately returns EAGAIN on its first read. The file position therefore remains zero, and a subsequent write overwrites the first byte. Direct P1 reads 'a' and writes at offset 1.

Confirmed with the standalone C program below, without any custom test driver or trace format. Each lane reproduced the same output 5/5 times in fresh directories on Wasmtime 46.0.0 (Release and Debug), 47.0.2, and 50.0.1. Wasmtime 50.0.1 was the latest upstream release at verification time.

Minimal reproducer (repro.c)

#include <errno.h>
#include <fcntl.h>
#include <stdio.h>
#include <string.h>
#include <unistd.h>

static void show_file(void) {
    char content[17] = {0};
    int fd = open("file.txt", O_RDONLY);
    ssize_t size = read(fd, content, 16);
    printf("file: rv=%zd content=%s\n", size, content);
    close(fd);
}

int main(void) {
    char byte = 0;
    int fd = open("file.txt", O_CREAT | O_TRUNC | O_WRONLY, 0644);
    write(fd, "abcdefghijklmnop", 16);
    close(fd);
    fd = open("file.txt", O_RDWR | O_NONBLOCK);
    errno = 0;
    ssize_t read_rv = read(fd, &byte, 1);
    printf("read: rv=%zd errno=%d (%s) byte=%c\n", read_rv, errno,
           strerror(errno), read_rv == 1 ? byte : '?');
    errno = 0;
    ssize_t write_rv = write(fd, "A", 1);
    printf("write: rv=%zd errno=%d (%s)\n", write_rv, errno, strerror(errno));
    close(fd);
    show_file();
    return 0;
}

Exact commands

Run in a new empty directory. The first command downloads the official v50.0.1 command adapter; clang, wasm-tools, and wasmtime must be on the stated paths or adjusted to local installations.

curl -fLO https://github.com/bytecodealliance/wasmtime/releases/download/v50.0.1/wasi_snapshot_preview1.command.wasm
/opt/wasi-sdk/bin/clang --target=wasm32-wasip1 -std=c17 -O2 -Wall -Wextra -Werror repro_rc_nb_read_eagain.c -o repro_p1.wasm
wasm-tools component new repro_p1.wasm --adapt wasi_snapshot_preview1=wasi_snapshot_preview1.command.wasm -o repro_adapter.wasm
wasmtime run --dir . repro_p1.wasm; wasmtime run --dir . repro_adapter.wasm

Expected vs. actual output (Wasmtime 50.0.1)

Direct P1 (expected):

read: rv=1 errno=0 (Success) byte=a
write: rv=1 errno=0 (Success)
file: rv=16 content=aAcdefghijklmnop

Adapter P2 (actual):

read: rv=-1 errno=6 (Resource temporarily unavailable) byte=?
write: rv=1 errno=0 (Success)
file: rv=16 content=Abcdefghijklmnop

Root cause

A host FileInputStream starts in ReadState::Idle. Its nonblocking read starts a blocking task and immediately returns empty Bytes; Waiting also returns empty Bytes (filesystem.rs:116-139). The adapter maps every nonempty request that returns empty bytes to ERRNO_AGAIN (lib.rs:2606-2610). Since no data was returned, fd_read does not advance file.position (lib.rs:1324-1329).

For a regular file, this exposes the initial asynchronous scheduling state as EAGAIN before either file data or a real permission error is available. The same code remains in v50.0.1.

Suggested fix and causal evidence

For regular files, wait for the initial host read to resolve instead of translating Idle/Waiting empty results directly to EAGAIN. A v46 causal patch used this intervention; the EAGAIN and overwrite disappeared 3/3, returned 3/3 after revert. A complete fix also needs the separate cached-input invalidation described in the stale-read issue when testing a subsequent read.
