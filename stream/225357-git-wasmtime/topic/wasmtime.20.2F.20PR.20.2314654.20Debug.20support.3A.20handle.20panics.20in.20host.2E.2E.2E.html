cfallin opened PR #14654 from cfallin:fix-debug-handler-panic to bytecodealliance:main:

If the debugger handles a hostcall-error debug event by panicking, that panic currently happens within the raise() libcall, which itself must not panic (because previously, it never ran user host code). A panic in that context would abort the process (because it would happen in an extern "C" function).

This PR wraps the debug event handler invocation in a catch_unwind and, if a panic occurs in the debug hook, replaces the unwind reason with that panic.
