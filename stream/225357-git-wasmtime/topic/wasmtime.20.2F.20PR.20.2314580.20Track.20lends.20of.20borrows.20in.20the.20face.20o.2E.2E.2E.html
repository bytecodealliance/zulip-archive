alexcrichton opened PR #14580 from alexcrichton:track-more-borrows to bytecodealliance:main:

Since resources were originally implemented in Wasmtime it's only ever tracked lends of own handles. This was all that was necessary in a fully synchronous world, but with async no in the picture this is no longer sufficient. Notably lends of borrows need to be tracked due to the nature of async functions. The spec has always tracked lends of everything, and it's just Wasmtime's historical optimization that's no longer applicable.

This is a behavior change for guests, but guests which now run into a trap were already likely running into odd behavior. Guest tables could get corrupt in the face of async with mismatched lends and such. This could cause spurious traps or crashes within the guest itself, but this never results in host-side crashing behavior.
