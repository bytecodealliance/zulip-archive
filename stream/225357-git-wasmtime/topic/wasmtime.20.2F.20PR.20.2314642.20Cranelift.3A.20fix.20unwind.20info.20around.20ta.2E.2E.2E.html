cfallin opened PR #14642 from cfallin:fix-tail-unwinding to bytecodealliance:main:

While Wasmtime doesn't use the DWARF unwind info / frame definitions, it is still useful to try to get them to be as correct as possible, because native debugging and especially native profiling (perf record, samply, etc) use this info.

Previously, the definition of the CFA did not quite stay in sync with a valid frame when we move the frame due to a resizing argument area on tail-calls. This PR reworks the metadata to instead define the CFA in terms of the FP and leave FP unchanged until we switch to the new frame.
