Fixes #14926

Why this change is needed

When inlining functions that contain interrupt_poll or compiling functions where an interrupt_poll possesses user stack maps, Cranelift encountered several issues:

  1. Inliner Crash / Unknown Call Opcode: interrupt_poll has Opcode::is_call() == true because it transfers control to the runtime interpreter, but it lacks a FuncRef / external callee body. The inliner previously hit the unhandled call assertion.
  2. Calling Convention Invariant: The IR verifier mandates that interrupt_poll only appears in functions with the tail calling convention. Inlining a tail callee containing an interrupt_poll into a caller with a different convention (e.g. system_v) resulted in invalid CLIF.
  3. Exception Table Fixups: When inlining into a try_call site, exception table fixups attempted to inspect interrupt_poll as a callable target.
  4. Backend Safepoints & Stack Map PC: Neither the x64 nor AArch64 backends classified InterruptPoll as a safepoint (is_safepoint()), and stack maps were not attached to the faulting load instruction PC where runtime signal handlers inspect frame state.
  5. Consecutive Stack Map PC Collision: In rare cases where a preserve_all call immediately precedes an interrupt_poll and both have stack maps, the call return PC and the faulting load PC coincide, violating exact-PC stack map uniqueness.

Implementation Highlights

  • Inliner (cranelift/codegen/src/inline.rs):
    • Allowed interrupt_poll to pass through the instruction-copying loop without tripping the unhandled call assertion.
    • Added can_inline check requiring callers to have CallConv::Tail if the callee contains interrupt_poll; non-tail callers preserve the out-of-line call.
    • Restricted exception table fixup candidates to Call, CallIndirect, TryCall, and TryCallIndirect.
  • ISA Backends (cranelift/codegen/src/isa/{x64, aarch64}/inst/):
    • Updated is_safepoint() to return true for Inst::InterruptPoll.
    • Emitted user stack maps at the address of the faulting load (sink.cur_offset()).
    • Emitted an architecture-specific NOP (x64: 0x90, AArch64: 0xd503201f) when a preceding call stack map shares the same PC with the poll's stack map.
  • MachBuffer & Disassembly (buffer.rs, write.rs):
    • Added MachBuffer::last_user_stack_map_pc() to detect PC collisions.
    • Generalized write.rs to print user stack maps for any safepoint instruction in textual CLIF output.
  • Regression Tests (cranelift/filetests/):
    • Added 5 new CLIF fixtures covering inliner behavior, x64/AArch64 stack map emission, and consecutive call/poll PC collision handling.

Fixes #14926

Why this change is needed

When inlining functions that contain interrupt_poll or compiling functions where an interrupt_poll possesses user stack maps, Cranelift encountered several issues:

  1. Calling Convention Invariant & Safepoint Mapping: interrupt_poll is a safepoint at which stack maps must be emitted at the faulting load instruction PC for signal handler inspection.
  2. Opcode Classification: Following review feedback from @cfallin, interrupt_poll does not have a callee, arguments, or calling convention (signal handlers are transparent to control flow). It is therefore classified without .call(), but retains safepoint handling (is_safepoint()).
  3. Inlining Logic: Because interrupt_poll is not classified as a call, the inliner copies it directly in the instruction-copying loop, and stack map entries are cleanly copied using opcode.is_safepoint().
  4. Backend Safepoints: Both x64 and AArch64 backends classify InterruptPoll as a safepoint (is_safepoint()), emitting user stack maps at the address of the faulting load without artificial NOP padding.

Implementation Highlights

  • Instruction Definition (cranelift/codegen/meta/src/shared/instructions.rs):
    • Removed .call() classification from interrupt_poll.
  • Inliner (cranelift/codegen/src/inline.rs):
    • Simplified inlining loop: uses opcode.is_safepoint() for copying user stack map entries, while reserving call/try_call exception table fixups strictly for actual call instructions.
  • ISA Backends (cranelift/codegen/src/isa/{x64, aarch64}/inst/):
    • is_safepoint() returns true for Inst::InterruptPoll.
    • User stack maps emitted at the exact faulting load address without artificial NOP insertion.
  • Regression Tests (cranelift/filetests/):
    • Updated CLIF filetests to reflect revised inlining and emission behavior.
