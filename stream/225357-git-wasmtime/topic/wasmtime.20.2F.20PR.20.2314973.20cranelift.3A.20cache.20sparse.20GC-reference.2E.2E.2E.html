leventov opened PR #14973 from convex-in-prod:upstream-sparse-gc-liveness to bytecodealliance:main:

Motivation

GC-reference liveness currently scans every instruction on every fixed-point visit and again when recording safepoints. Most instructions in scalar-heavy functions cannot change that liveness set.

Change

Record the relevant definitions, uses and safepoints once, in the same backwards order as the existing analysis, and reuse those events for subsequent visits. Alias resolution, try-call edge argument ordering, exception-context rejection and live-set propagation retain their existing semantics. Empty safepoint sets do not need recording, and functions with no reference live across any safepoint skip rewriting.

Event storage is reused with the builder context and cleared between functions. A regression alternates dead/live/dead reference lifetimes in scalar-heavy functions using the same context, checking that spills and reloads appear only when required.

Validation

cargo test -p cranelift-frontend --lib safepoints: all 22 tests passed, including loops, irreducible control flow, aliases, try-call edges and context reuse. The new regression was rerun after updating its scalar instruction builder to the current nondeprecated API. Changed-file rustfmt check passed.

The intended benefit is less work in repeated liveness visits; this PR does not change generated stack-map semantics or claim a universal compilation speedup. It adds a compact event list whose size depends on references and safepoints, rather than scalar instruction count.

Both variants used the same input and engine settings, one AOT worker pinned to a single CPU, and independently populated function caches. Order Variant Elapsed seconds CPU seconds Function-cache misses

Across the two invocations per variant, elapsed time fell 27.0% (122.572 → 89.500 s) and CPU time fell 28.0% (116.07 → 83.52 s), with matched miss counts. Every invocation reproduced the same approximately 569 MB AOT artifact byte for byte. This matters for incremental builds: frontend liveness work still runs even when almost all compiled function bodies can be reused.

This is a historical downstream measurement of the change, not a rerun on this PR's current upstream base. It measures remaining AOT work with warm function caches, not cold compilation, the complete application build, or guest execution. There are only two observations per variant; the result illustrates a workload where the change helps rather than predicting a universal compilation speedup.
