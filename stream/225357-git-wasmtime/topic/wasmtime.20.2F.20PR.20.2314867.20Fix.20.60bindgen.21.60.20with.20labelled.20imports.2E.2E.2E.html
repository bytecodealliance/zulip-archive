jrandolf opened PR #14867 from jrandolf:bindgen-labelled-imports to bytecodealliance:main:

This fixes several bindgen! bugs with labelled (implements) imports and exports, one commit each:

  • Plain and labelled import of one interface. A world like import store; import a: store; generated the bindings module for store twice and failed with E0428. The same happened when the plain import came in through use or include (e.g. include wasi:cli/imports@0.3.0; import a: wasi:cli/environment@0.3.0;), in either order, and with with remappings. Labelled imports now reuse the plain import's bindings, and the world's add_to_linker binds the interface under its own name and under each label.
  • named_imports keys. A key naming an interface that exists but isn't imported by the world panicked the macro with no entry found for key; it's now an error. Keys are also matched the same way as with, so an unversioned key applies to every imported version of the interface instead of just the first one found.
  • @unstable on labelled imports. Every label of an interface got the feature gate of the first label, since the gate was looked up by interface id. It's now looked up by label.
  • Conflicting export names. Labels can clash with the modules and accessors generated for interface exports (e.g. export foo: greeter; export greeter; in package foo:foo) or with the world's own methods. That used to generate code that failed to compile with confusing errors. It's now reported as an error naming both exports.

There's no harness for proc-macro errors, so the error cases are unit tests in crates/wit-bindgen/tests/errors.rs that call Opts::generate directly. Most of the diff is new snapshots.

Closes #14855
Closes #14856
