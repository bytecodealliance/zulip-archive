This commit removes the ConcreteExn variant from the public API of Wasmtime and its HeapType enum. I brought this up earlier in #14011 which was closed, but I'd like to push on this again at least from the angle of the public API of Wasmtime. Specifically this fixes a possible unusual situation where:

  • A host function is created with HeapType::ConcreteExn as one of its arguments.
  • This function is called with a different kind of concrete exception.
  • Due to a missing type check which in theory shouldn't actually be necessary, this actually passes at runtime.

There's no panic/etc here and this is just a weird situation, but this exposes a part of exposing ConcreteExn in the public API which is that it affects not just what's read from WebAssembly but what's also passed back in from the host. For example creating a GC struct type with concrete exception types doesn't really make sense, but it's possible with today's embedder API.

This change is not as invasive as #14011 and only limits the public API surface area of Wasmtime. The goal is to have the public API faithfully reflect wasm's type system to avoid introducing our own abstractions and having to reconcile that.
