alexcrichton opened PR #14590 from alexcrichton:fix-some-overflow to bytecodealliance:main:

This commit fixes a few possible overflowing additions that can happen during compilation when some tunables are set to extremely high values such as memory_reservation or memory_guard_size. These are already handled correctly at runtime such that a memory could never actually be instantiated, but the compile-time phase of things has a few additions which would panic in debug mode. It felt best to just disallow this in the Config-layer of options to avoid having to worry in the runtime about these values overflowing.
