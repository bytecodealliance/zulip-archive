We previously had a workflow where we published the updated cache only from CI runs in main.yml, but because of branch scoping combined with our use of the merge queue, runs on "main" actually ran on a merge-queue temporary branch and thus did not update the cache contents in a location available for other runs. The main-scoped content was updated only by our once-per-night full CI run on main.

This commit updates publish-artifacts.yml to add a job to the flow that does run on main, after merge, on every merge: it fetches the artifact from the build we just did and publishes it to the GitHub cache. This way, cache updates from all changes that are merged will be immediately available to subsequent CI runs.
