This commit fixes a too-eager bounds-check for linear memories when they're imported, runtime configuration says memories cannot move, and the minimum size of the memory exceeds the runtime-configured default memory reservation. Imported memories are allowed to be larger than the declared minimum, and the default memory reservation is just a guideline and doesn't prevent memories being created larger than that. Effectively a special-case in bounds-checking just needed and extra clause to ignore imported linear memories because the special-case was inapplicable.

This fixes memory accesses that previously trapped to correctly fall back to a more general bounds check meaning that incorrect traps now succeed as they're supposed to.

Closes #14587
