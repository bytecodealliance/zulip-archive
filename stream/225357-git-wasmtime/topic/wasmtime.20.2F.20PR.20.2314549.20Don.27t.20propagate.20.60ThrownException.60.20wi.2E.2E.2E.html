This commit updates logic to handle the ThrownException built-in-error type when processing an otherwise-uncaught exception. Previously this had no special handling w.r.t. components and a consequence of that was that natural ?-style error propagation would "leak" exceptions across component boundaries. Components are intended to convert any uncaught exceptions into traps at component boundaries, but due to this ?-propagation it wasn't actually correctly implemented in a number of locations.

Some of the new tests added in this commit are examples of where these uncaught exceptions where ?-propagated across components. One example is that when a component calls task.return and then that calls realloc and then that throws an exception. Previously that was propagated through ? meaning that an exception thrown by the callee naturally transitioned into the caller across the component boundary.

The fix in this commit is intended to make ?-style propagation work-by-default with components. Namely uncaught exceptions are internally turned into Trap::UncaughtException instead of propagating as a ThrownException. This is done by annotating call-sites with what behavior is desired, where core wasm entrypoints propagate ThrownException and component entrypoints all turn it into a trap.
