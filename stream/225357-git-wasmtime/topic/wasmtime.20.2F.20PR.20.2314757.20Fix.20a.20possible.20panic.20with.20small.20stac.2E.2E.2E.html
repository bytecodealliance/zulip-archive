alexcrichton opened PR #14757 from alexcrichton:fix-pulley-small-stack to bytecodealliance:main:

This commit fixes a possible panic that can happen when Pulley generates a trap where the stack is almost full or very small. The specific issue here is that the entry trampoline for Pulley can fail, unlike native platforms, because it's interpreted and has stack checks, unlike native platforms. If this entry trampoline fails then the backtracing implementation panics on an inconsistent state because an activation is expected but was never fully set up.

The fix in this commit is to handle this case when Pulley traps and skip getting a backtrace of the top-most activation. This is done with some light refactoring to plumb some Option-ality around.
