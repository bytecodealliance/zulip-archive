jrandolf opened PR #14835 from jrandolf:map-lift-validate-before-alloc to bytecodealliance:main:

Lifting a map<K, V> into a HashMap reserved capacity for the guest-supplied length before checking that the entries actually fit in linear memory. This moves the allocation after the bounds, alignment and fuel checks, the same order lists use.

For reference, before this change a guest with a single page of memory returning (ptr = 0, len = u32::MAX) for a map<u32, u32> made the host's peak RSS jump by about 8 GiB (hashbrown initializes its control bytes) before the call failed with the bounds error. The added test checks for that error; I couldn't find a non-flaky way to assert on the allocation itself, but I'm happy to add one if there's a preferred pattern.

Closes #14810
