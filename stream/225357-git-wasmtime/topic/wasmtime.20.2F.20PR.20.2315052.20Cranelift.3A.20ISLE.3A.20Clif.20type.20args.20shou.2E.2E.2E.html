avanhatt opened PR #15052 from avanhatt:isle-ctrl-ty to bytecodealliance:main:

Per discussion with @cfallin, when a Clif ISLE term has a type parameter, the type should always be the controlling type from the Clif definition (e.g., the width of x/y in (icmp ty x y)), not the result type (e.g., i8) when they differ. Make this change and update the affected rules (257 of them) and ISLE specs. This requires introducing a has_type helper into opt for cases where rules do intend to match on the result type.

Note this had the nice consequence of improving GVN due to it previously failing to deduplicate across the version of the instruction that correctly used the controlling type (before the egraph) and the one using the result type (in the egraph). I have not yet tried to measure if this has any performance impact. This PR also fixes more cases where opt rules were only firing at i8 due to the conflation of the two types (related to #14964).
