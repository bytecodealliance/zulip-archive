Report: https://github.com/bytecodealliance/wasmtime/issues/14694

Narrow (i8/i16) sdiv/udiv by a constant non-power-of-two divisor were left as trapping skeleton instructions, so they were not removed even when the result was unused (i32/i64 already were, via the magic-number rewrite). This extends i8/i16 operands to i32, reuses the i32 magic sequence, and reduces the result.

Validated with cargo test -p cranelift-filetests, cargo test -p cranelift-codegen, and new egraph and run tests (run on this aarch64 machine; x86_64/s390x/riscv64 targets in the run test were not executed here). Divisors of -1 and powers of two are excluded, so the INT_MIN / -1 trap is unchanged.

I used an AI tool to help with this change and reviewed it myself.

Fixes #14694
