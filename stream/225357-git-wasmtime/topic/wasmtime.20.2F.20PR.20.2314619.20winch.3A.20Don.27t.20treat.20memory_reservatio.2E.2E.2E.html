Closes: https://github.com/bytecodealliance/wasmtime/issues/14588

With memory_may_move disabled, Winch treated memory_reservation as an upper bound on accessible memory and turned any access whose offset + access size exceeded it into an unconditional trap. But when a memory's minimum size is larger than the reservation, the runtime sizes the allocation from the minimum instead, so in-bounds accesses past the reservation trapped spuriously.

The static out-of-bounds check now applies the reservation only when the memory's minimum byte size fits within it; otherwise the access falls through to a regular dynamic bounds check.
