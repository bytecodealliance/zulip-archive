Fixes #14584.

Store::wasm_fault asserts that only one instance in the store claims the faulting address. That doesn't hold for shared memories: importing one goes through SharedMemory::vmimport, which creates a single-memory instance that defines the same memory. So in the example from the issue, both $a and that instance report the fault, and the assert fires instead of the trap.

This keeps the check but only panics when the address belongs to two different memories, by comparing the wasm_address each instance reports. It doesn't compare memory_size, since a shared memory can be grown by another thread between the two reads.

I added the example from the issue as tests/misc_testsuite/threads/shared-memory-imported-oob.wast. It panics at store.rs:2061 on main and passes with this change. cargo test --test wast, cargo test --test all -- shared_memory threads traps and cargo test -p wasmtime --lib pass locally on macOS (aarch64).

I used Claude Code to reproduce the bug and test the fix locally.
