Previously addends for GOT relocations were interpreted as applying to the address of the target symbol, with a + 4 to correct for the bogus result and an explicit - 4 for determining the pcrel offset. The addend should instead be applied to the pcrel offset and ignored for the GOT value. This ensures addends other than -4 are correctly interpreted and prevents a panic for symbol addresses < 4 (eg when storing a constant directly in the symbol rather than a pointer to said constant)

Additionally stop hard coding the GOT size as 8 bytes big. If we get 32bit support in the future, the GOT should be 4 bytes big.

I noticed this while trying to add TLS support to cranelift-jit and noticing I got a panic whenever I tried to store an id for the TLS slot directly in the GOT entry as if it is the address of the TLS symbol.
