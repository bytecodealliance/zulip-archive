scothis opened PR #14543 from scothis:bindgen-prelude-conflict to bytecodealliance:main:

Generated bindings referred to Result, Option, and core::... items by bare or relative paths. These broke when a WIT interface defined a type whose name collides with a prelude item, such as type %result = bool; or type %option = bool;. The generated pub type Result = bool; would shadow the prelude, so later uses of Result<...> in the same module failed to compile.

Generated code now uses ::core::result::Result,
::core::option::Option, and ::core::... for the fmt, error, and convert traits. This way user-defined type names can't shadow them.

Add a codegen test with interface types named result and option, and regenerate the expanded test outputs.

A similar change was made in https://github.com/bytecodealliance/wit-bindgen/pull/1676
