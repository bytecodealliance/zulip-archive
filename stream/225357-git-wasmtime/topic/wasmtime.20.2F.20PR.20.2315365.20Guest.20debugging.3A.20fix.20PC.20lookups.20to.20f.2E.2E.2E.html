When guest debugging is enabled, a module used within a given store gets a private copy of the code. We call the original code "engine code" and the maybe-private copy "store code". We have newtypes around PCs for both (EngineCodePC and StoreCodePC). When guest debugging is disabled, we still call the actually executing copy the "store code"; it just happens to alias the engine code instead (no private copy).

Various parts of the runtime do lookups based on observed PCs in frames (e.g., trap code loop, GC stackmap lookup, and exception-handler lookup).

I wrote most of this code when the invariant was still that all code actually running in a given store would be "store code". Late in the implementation of guest debugging, I discovered it would not be easily possible to have a private copy of some trampolines, but that they were "store-invariant" (no breakpoint patching was possible since no guest Wasm program points were present in the trampolines), so it was fine to run the canonical/shared engine copy.

Unfortunately, the idea that we look up "store PCs" only is in conflict with this, and we thus would not find e.g. exception handlers in store-invariant trampolines (see #15332 for an example).

This PR generalizes things a bit: we can look up both engine PCs and store PCs in the per-store registry, and we can get a sum-type result that can represent a PC found in either kind of copy. We can look up metadata and derive exception-handler PCs from either kind of hit. We then use this in all the relevant places that we do PC lookups.

Fixes #15332.
