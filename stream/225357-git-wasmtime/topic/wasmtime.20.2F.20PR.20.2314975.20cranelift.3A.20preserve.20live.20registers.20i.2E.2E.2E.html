Motivation

Fuel and epoch checks expose uncommon builtin calls to the register allocator. Treating those handlers as ordinary caller-clobbering calls imposes register constraints and spills on instrumented code even when the slow branch is not taken.

Change

Use the existing PreserveAll builtin trampoline for out_of_gas and new_epoch, and mark the fuel slow block cold. The preserving trampoline has no return registers, so epoch checks reload the authoritative deadline from the Store after the callback, including after async suspension. Existing fuel reloads remain in place.

This changes neither fuel charges nor epoch-check placement. It adds no polling configuration or new public runtime API. It relies on the existing preserving trampoline and safepoint machinery used for patchable builtins.

Validation

All four focused tests in tests/all/metering_preserve.rs passed on the extracted branch with Rust 1.97.1 and the copying collector. The exact test file was compiled in a small external harness against this branch with Cranelift, async, GC and call hooks enabled, avoiding unrelated CLI/WASI dependencies. Changed-file formatting and diff checks passed.

The focused tests keep integer, floating-point and SIMD values live across refill and epoch callbacks; compare exact fuel consumption; cover yielding, interruption, callback errors, cancellation and store reuse; and retain references across metering yields and moving collection. This is intended to reduce the cost of ordinary execution, not to make the slow handlers themselves cheaper.
