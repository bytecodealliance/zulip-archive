po-nuvai opened PR #15130 from po-nuvai:fix-15036-elem-eval-order to bytecodealliance:main:

Active element segments whose expressions may trap (struct.new* / array.new*) are now evaluated up front, alongside passive segments, into a hidden segment slot that wasm code cannot access. They are then copied into their table in the normal active-segment order and dropped. This means a trapping element expression no longer leaves earlier writes behind in imported tables, matching the spec. Segments that cannot trap keep the existing fast path.

The cow-order-trapping-elem-expr.wast test expected the old behavior (an earlier segment's write remaining in the imported table), so it is updated to expect an uninitialized element instead.

Fixes #15036
